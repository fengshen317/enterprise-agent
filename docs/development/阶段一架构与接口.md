# 阶段一架构与接口

日期：2026-11-03。本文描述阶段一基线。阶段二已新增业务模型与 0002 迁移，当前迁移已到 0005，就绪检查要求 schema_version=5；增量结构见 [阶段二数据模型](阶段二数据模型.md)，阶段一验收记录保留当时版本。

## 模块职责

- frontend/src/api/：HTTP 请求、超时、错误处理和响应结构验证。
- frontend/src/views/：系统状态页面；分别展示进程存活和数据库就绪结果。
- frontend/src/styles/variables.scss：统一 SCSS 变量；main.scss 为 BEM 布局。
- backend/app/api/：异步路由，不直接管理连接池生命周期。
- backend/app/core/config.py：独立数据库字段配置、端口与超时校验。
- backend/app/core/database.py：应用级连接池、请求级独立会话；退出时关闭连接池。
- backend/app/core/errors.py：自定义异常与框架异常统一响应。
- backend/app/core/logging.py：JSON 应用日志。
- backend/app/models/：模型元数据与系统初始化标记。
- backend/alembic/：独立执行迁移，不在 API 启动时修改结构。

本阶段不提前建立空的 Agent、知识库或任务抽象。后续模块按实际业务引入。Pinia、Element Plus、Deep Agents SDK 待使用时安装。

## 请求流程

前端通过 Vite /api 代理调用 FastAPI。API 为请求生成 request_id，在响应头和错误正文中返回；就绪接口创建独立数据库会话，查询初始化标记。完成请求时关闭会话并回滚未提交事务。

前端并行检查 live 和 ready，单项失败不覆盖另一项结果；支持重试，并在错误时展示关联标识。

## 健康接口

|方法与路径|成功响应|失败语义|
|---|---|---|
|GET /api/health/live|200，status=ok|仅判断 API 可响应，不连接数据库|
|GET /api/health/ready|200，status=ready|数据库不可用、超时或缺少初始化表时 503；标记不存在或版本不符时 503|

成功正文：

~~~json
{"status":"ready","service":"enterprise-agent-api","version":"0.1.0"}
~~~

错误正文：

~~~json
{"error":{"code":"DATABASE_UNAVAILABLE","message":"数据库未就绪，请检查连接与迁移状态"},"request_id":"服务生成的32位标识"}
~~~

所有响应包含 X-Request-ID。错误码：

- DATABASE_UNAVAILABLE：连接异常、查询超时或初始化表不可访问。
- SCHEMA_NOT_READY：schema_version 不存在或不匹配。
- VALIDATION_ERROR：422 参数校验失败，不回显原始输入。
- HTTP_404 / HTTP_405 等：框架路径或方法错误。
- INTERNAL_ERROR：未预期异常，隐藏内部详情。

接口 OpenAPI 见 /docs 与 /openapi.json；自定义运行时错误结构以本文和契约测试为准。当前就绪检查只验证初始化标记，不等价于验证未来所有业务表；结构漂移通过 alembic check 检查。

## 数据模型与迁移

迁移版本：0001。

|system_metadata 字段|类型|约束|
|---|---|---|
|key|varchar(64)|主键|
|value|varchar(255)|非空|
|created_at|带时区时间戳|非空，数据库默认当前时间|

迁移插入 key=schema_version、value=1 的基础标记。该表不保存业务配置或密钥。Alembic 自身使用 alembic_version 追踪迁移版本。

独立测试库验证 upgrade → check → ready → downgrade → 表移除 → upgrade。不要在包含业务数据的数据库上照搬测试降级流程。

## 日志与配置边界

应用日志字段包含 timestamp、level、logger、event、request_id、method、path、status_code、duration_ms，异常日志附 error_type。当前不记录查询参数、请求正文、数据库 URL 或任意附加字段。请求标识由服务端生成。Uvicorn 生命周期日志由 Uvicorn 自身管理。

配置中的 database_password 使用 SecretStr 避免普通配置 repr 泄露，sqlalchemy_url 通过 URL.create 按字段创建，连接池和 Alembic 均直接使用 URL 对象，不手动拼接或编码密码；这不代替日志审查。进程退出时释放连接池；异步并发任务不能共享同一个 AsyncSession。

## 测试边界

- 后端契约测试替换数据库会话，验证存活、就绪、失败、超时、错误脱敏、CORS 与日志。
- 集成测试使用本机真实 PostgreSQL 的独立测试库，验证迁移、元数据一致性和真实查询。
- 前端使用 Vitest 与 jsdom，验证响应语义、错误处理、独立状态展示与重试。
- HTTP 联调验证实际前后端与代理；jsdom 和 HTTP 检查不等价于真实浏览器视觉验收。
