# 个人模型配置

所有完成首次改密的登录用户可从账号区的「模型配置」进入 `/account/models`。

## 使用方式

- 「我的模型」保存当前账号的独立模型配置。选择厂商、输入该厂商 API Key 后，可获取模型目录或手动填写模型 ID，并测试连接。
- 保存时可勾选「设为我的默认模型」，保存和默认选择在同一事务提交。默认选择跟随账号，在各工作空间使用。
- 「空间模型」展示系统管理员统一提供的公共默认模型，点击「跟随空间默认」清除本人的覆盖选择。
- 个人模型使用个人 API Key 的额度。厂商返回的目录只表示列出的模型，实际可用性由连接测试和供应商权限决定。

## 权限与存储

个人接口使用 `IdentityDependency`，沿用 Cookie、Origin、CSRF 和初始密码改密校验。客户端无法指定所有者。普通成员的出站模型地址限定为内置厂商地址，系统管理员仍可在部署配置中管理自定义接口。

复用 `integration_configs` 保存加密的 `ModelProfileDraft`。个人记录使用 `personal-model:<UUID>`，通过 `updated_by` 绑定账号。默认指针使用 `personal-active:<user UUID hex>`。管理员公共档案使用原有前缀，二者在查询和激活时分别校验。响应只返回 `has_api_key`，所有个人模型接口禁止缓存。

复用持久化的集成配置加密密钥文件。已存在个人档案或运行快照时，密钥文件丢失会返回固定错误，阻止自动生成替代密钥。个人模型不可读或调用失败时返回错误，由用户选择后续模型。

## 运行链路

网页、微信和定时问答均通过 `ChatRuntime.create_run` 解析运行所属账号的默认模型。迁移 `0030` 给 `runs` 增加可空的 `model_connection`，以密文固定提交时的供应商、地址、文本和图片模型及本轮密钥。创建消息和快照在同一事务写入。

执行阶段从快照构造独立 `Settings` 和 SDK 客户端，用于上下文压缩、主模型及子 Agent。切换默认模型仅影响后续提交。HTTP、SSE、工具审计及模型消息不会包含密文连接字段。升级前无快照的运行兼容公共默认配置，原有取消、重试、流式展示及权限撤销流程继续生效。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/me/models` | 本人模型与脱敏公共默认项 |
| POST | `/api/me/models` | 保存个人模型，可带 `make_default` |
| POST | `/api/me/models/{id}/activate` | 激活本人的模型，其他账号的 ID 返回 404 |
| POST | `/api/me/models/follow-shared` | 恢复公共默认 |
| GET | `/api/me/models/providers` | 内置厂商 |
| POST | `/api/me/models/providers/{id}/models` | 用本次凭据查询目录 |
| POST | `/api/me/models/test` | 使用独立密钥测试文本及可选图片模型 |

## 验证范围

`test_personal_models.py` 使用真实 PostgreSQL 与真实登录会话，检查普通成员入口、越权、CSRF、地址限定、密文存储、密钥缺失和本轮模型快照。模型调用使用受控替身验证凭据路由，供应商实付请求仍需真实凭据验收。前端测试覆盖目录发现、保存个人默认及恢复公共默认。

## 合并主线后的迁移顺序

主线的 `0029` 保留企业通讯渠道表，本功能的运行快照顺延至 `0030`，就绪检查要求版本 `30`。生产和新测试库直接执行 `alembic upgrade head`。

如果本地曾提前应用功能分支同名的旧 `0029_personal_model_runs`，应先备份开发库并核对：已有 `runs.model_connection`，但不存在 `channel_apps`。仅在确认属于这种本地版本冲突时，将 Alembic 标记恢复至 `0028` 后再执行升级；`0030` 会保留已存在的快照列。已应用企业渠道 `0029` 的数据库不可按此方式修改标记。

合并验收：后端完整回归 594 项通过、7 项跳过；流式首段测试因 Windows 冷启动超过原 10 秒预算失败，等待预算调整为 30 秒后复测通过，保留提前可见及重试替换内容的行为断言。累计 595 项通过，覆盖率 81.30%。前端 221 项、lint、类型检查及构建通过；后端 Ruff、严格 Mypy 通过。

## MiMo 工具调用适配（2026-11-27）

小米官方兼容地址 `api.xiaomimimo.com` 在统一 LLM 工厂中显式发送 `thinking.type=disabled`，覆盖问答、摘要、计划、子 Agent、图片模型和连接测试。MiMo 默认开启思考，思考与正文共同消耗 `max_completion_tokens`；当前兼容 SDK 不完整保留其 `reasoning_content`，因此不默认启用思考模式。其他兼容地址不注入该参数。参考 [MiMo 官方深度思考文档](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/other/deep-thinking)。

模型返回 `finish_reason=length` 时，已生成且不包含工具调用的正文作为部分结果保存，运行仍标为 `MODEL_OUTPUT_TRUNCATED`，不能当作完整成功。没有正文时不会编造结果，工具参数截断也不会发布为正文。

回归验证使用真实 SDK 图和受控 HTTP，覆盖 MiMo 请求参数、其他供应商保持兼容及截断正文保留；不将模拟供应商响应作为真实邮箱读取成功的证据。

本次修复验证：模型适配测试 15 项、真实 PostgreSQL 工具与对话 Agent 回归 32 项全部通过，Ruff 与全后端严格 Mypy 通过。测试供应商使用受控 HTTP；真实 QQ 邮箱内容读取需单独验收。
