# 个人模型配置

所有完成首次改密的登录用户可从账号区的「模型配置」进入 `/account/models`。

## 使用方式

- 「我的模型」保存当前账号的独立模型配置。选择厂商、输入该厂商 API Key 后，可获取模型目录或手动填写模型 ID，并测试连接。
- 保存时可勾选「设为我的默认模型」，保存和默认选择在同一事务提交。默认选择跟随账号，在各工作空间使用。
- 「空间模型」展示系统管理员统一提供的公共默认模型，点击「跟随空间默认」清除本人的覆盖选择。
- 个人模型使用个人 API Key 的额度。厂商返回的目录只表示列出的模型，实际可用性由连接测试和供应商权限决定。

## 权限与存储

个人接口使用 `IdentityDependency`，沿用 Cookie、Origin、CSRF 和初始密码改密校验。客户端无法指定所有者。普通成员的出站模型地址限定为内置厂商地址，系统管理员仍可在部署配置中管理自定义接口。

复用 `integration_configs` 保存加密的 `ModelProfileDraft`。个人记录使用 `personal-model:<UUID>`，通过 `updated_by` 绑定账号。默认指针使用 `personal-active:<user UUID hex>`。管理员公共档案使用原有前缀，二者在查询和激活时分别校验。响应只返回 `has_api_key`，所有个人模型接口禁止缓存。

复用持久化的集成配置加密密钥文件。已存在个人档案或运行快照时，密钥文件丢失会返回固定错误，阻止自动生成替代密钥。个人模型不可读或调用失败时返回错误，由用户选择后续模型。

## 运行链路

网页、微信和定时问答均通过 `ChatRuntime.create_run` 解析运行所属账号的默认模型。迁移 `0029` 给 `runs` 增加可空的 `model_connection`，以密文固定提交时的供应商、地址、文本和图片模型及本轮密钥。创建消息和快照在同一事务写入。

执行阶段从快照构造独立 `Settings` 和 SDK 客户端，用于上下文压缩、主模型及子 Agent。切换默认模型仅影响后续提交。HTTP、SSE、工具审计及模型消息不会包含密文连接字段。升级前无快照的运行兼容公共默认配置，原有取消、重试、流式展示及权限撤销流程继续生效。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/me/models` | 本人模型与脱敏公共默认项 |
| POST | `/api/me/models` | 保存个人模型，可带 `make_default` |
| POST | `/api/me/models/{id}/activate` | 激活本人的模型，其他账号的 ID 返回 404 |
| POST | `/api/me/models/follow-shared` | 恢复公共默认 |
| GET | `/api/me/models/providers` | 内置厂商 |
| POST | `/api/me/models/providers/{id}/models` | 用本次凭据查询目录 |
| POST | `/api/me/models/test` | 使用独立密钥测试文本及可选图片模型 |

## 验证范围

`test_personal_models.py` 使用真实 PostgreSQL 与真实登录会话，检查普通成员入口、越权、CSRF、地址限定、密文存储、密钥缺失和本轮模型快照。模型调用使用受控替身验证凭据路由，供应商实付请求仍需真实凭据验收。前端测试覆盖目录发现、保存个人默认及恢复公共默认。
