## 3. 真实数据库集成覆盖

17 项集成测试覆盖以下边界：

- 创建任务幂等；确认前不执行工具，普通问答不自动创建任务；统计来自 Conversation/Run，不包含 TaskRun。
- 相同目标复用任务、同键不同目标拒绝；管理员也不能读取或控制其他成员的私有任务；匿名、CSRF 与伪造身份字段拒绝。
- 计划修订追加版本；确认绑定 run_id/revision/digest，编辑绑定 run_id/revision；旧计划确认、旧执行和旧版本控制返回 409。
- 临时 503 只增加本动作请求尝试；403 永久错误不自动重试，手动 retry 创建新 TaskRun 并保留旧执行。
- 模型重试不重做已成功工具；失败片段和敏感异常正文不拼接到结果。
- Retry-After 进入持久化等待，取消后不发新请求；长等待暂停后 resume 仍保留同一最早时间，不提前重试；等待超过总截止时间直接失败。
- 暂停/取消阻断迟到提交；两路独立步骤可并行，汇总等待两路依赖；一个分支失败时另一分支不遗留 running 请求尝试。
- 真正关闭旧 TaskRuntime、新建实例 start，未再发 HTTP 任务请求前后台扫描自行恢复同一 TaskRun；成功工具动作仍只有一次真实执行，未完成请求留下 interrupted 记录。
- 租约恢复递增 fencing_token，旧 token 提交拒绝；过期及撤权在恢复前失败，静默模型期间撤权也停止飞行请求与结果发布。

### 数据库约束

测试库显式重建 0008 后完成模型比对，再使用 savepoint 验证拒绝写入：

- Task.current_run_id 指向其他 Task 的 Run，SET CONSTRAINTS ALL IMMEDIATE 时拒绝可延迟复合外键。
- TaskAction/TaskStep 的 succeeded 状态缺少 result。
- ActionAttempt/StepAttempt 的 attempt_no=0。
- 请求尝试或 TaskRun 的终态没有完成时间。
- 租约 owner/expiry 只设置一边。

失败写入回滚到保存点，不破坏合法任务和原执行指针。数据库约束验收使用专用测试库，不对开发库做降级/重建。

### 补充故障恢复回归

此外 test_task_retry_recovery.py 的 4 项真实 PostgreSQL 回归已单独通过（不计入前述 65 项专项）：

- 在 finish_action 真实事务提交之后注入“提交确认丢失”，失败尝试、动作等待、Run 等待和 Retry-After 仍同时保留，恢复不能提前发第二请求；测试显式推进持久化时间，不真实等待两分钟。
- 永久 403 失败已提交，但 TaskRun 尚未标记失败时模拟中断，恢复直接读取失败决策，不重发供应商请求。
- 动作成功和失败各自推进快照 version、事件 sequence，并存在对应 action_succeeded/action_failed 事件。

finish_action 当前把失败分类、请求终态、动作最早重试时间、步骤/Run 等待或长暂停及事件放在同一事务，消除“已记失败但未记等待”的恢复窗口。该测试模拟应用丢失提交确认，不将其描述为已经完成真实数据库服务器断电演练。
