# 知识库实现与验收

日期：2026-11-12。状态：MVP + 详情页增强 + 自动检索注入已实现，迁移 `0013`。目标 RAGFlow：本地 1.0 实例。

## 一、已实现范围

- 应用侧知识库与文档元数据、权限和工作空间隔离。
- 一个应用知识库对应一个 RAGFlow dataset。
- 两级页面：`/knowledge` 列表页与 `/knowledge/:kbId` 详情页。
- 知识库创建、列表、详情、编辑、删除；列表/详情返回文档数和 chunk 数。
- 文档上传（多文件串行队列）、文档级解析配置 PATCH、解析状态与进度、失败原因、重新解析、删除。
- 原文件下载与在线预览：PDF/图片/纯文本浏览器内联，Markdown 映射纯文本，HTML/SVG 等强制下载。
- 只读分块浏览：分页查看 chunk 内容和可用状态。
- 解析配置：预设模板（通用/手册/FAQ）+ parser_id + 分块参数 + PDF 解析方式 + 自动关键词/问题提取。
- 检索测试：详情页直接调 top_k/阈值，查看命中内容、来源和相似度。
- “应用到已有文档并重新解析”：同步知识库配置后批量 reparse。
- 检索工具 `search_knowledge_base`，主 Agent 和子 Agent 均可使用。
- **自动知识库检索注入**：每次提问后端自动检索可访问知识库，把 chunk 编号后注入模型上下文，不依赖模型调工具。回答下方展示来源卡片，正文用 [1][2] 标注引用。
- 检索结果带应用侧文档来源，不暴露 RAGFlow dataset/document/chunk ID。
- RAGFlow API Key 只在后端使用，前端不直连 RAGFlow。

## 二、未实现范围

- 后台解析状态轮询 Worker；当前在文档列表请求时同步，前端解析中每 5 秒轮询。
- 跨空间 RAGFlow 团队/租户隔离；MVP 使用单服务账号。
- 检索评测集、PDF/OCR/表格解析质量的独立验收。

## 四、权限规则

| 操作 | 规则 |
|---|---|
| 列表/查看 | 当前空间的 `workspace` 知识库；自己的 `private` 知识库 |
| 创建空间知识库 | 仅空间 `admin` |
| 创建私有知识库 | 任意有效成员 |
| 管理空间知识库 | 空间 `admin` 或创建者 |
| 管理私有知识库 | 仅创建者；管理员也不能读取或管理他人的私有库 |
| 上传/解析/删除/下载/分块 | 继承知识库读/管理权限 |
| 检索 | 当前 Run 的用户/空间 + 知识库可见性；模型不能传 RAGFlow 身份 |
| 审计 | 复用 `tool_calls`；只保存查询、文档 ID/名称、相似度，不保存完整正文 |

## 五、RAGFlow 1.0 适配要点

- 创建 dataset：`parse_type` + `parser_id`，不发送 `chunk_method`。
- 更新 dataset：`parse_type` + `parser_id` + `parser_config`。
- 上传文档：只发送文件；上传接口的 `parser_config` 会被忽略。
- 上传后必须用 `PATCH /datasets/{ds}/documents/{doc}` 写入解析配置，再调用 `/chunks` 解析。
- 原文件下载：`GET /datasets/{ds}/documents/{doc}`，返回二进制体和 `Content-Disposition`。
- 分块列表：`GET /datasets/{ds}/documents/{doc}/chunks`，分页参数是 `page` + `page_size`（`size`/`offset`/`limit` 不生效）。
- 局部 `parser_config` 会深度合并；组件名可能带实例混淆后缀，客户端按 `Parser:`/`Extractor:`/`GeneralChunker:` 前缀回退定位。
- 解析状态使用 `UNSTART` / `RUNNING` / `COMPLETED` / `FAIL` / `CANCEL`；同时兼容数值 `0–4`。
- 文档列表单页上限 100，客户端自动分页。
- 检索使用 `dataset_ids` / `document_ids` 过滤；未发现任意 metadata 过滤。
- 检索阈值默认 0.2；唯一 Token 查询的相似度可能只有 0.3–0.4，需要评测调参。

## 六、API

```text
GET    /api/knowledge-bases
POST   /api/knowledge-bases
GET    /api/knowledge-bases/{id}
POST   /api/knowledge-bases/{id}
POST   /api/knowledge-bases/{id}/delete
POST   /api/knowledge-bases/{id}/retrieval-test
POST   /api/knowledge-bases/{id}/reparse-documents
POST   /api/knowledge-bases/{id}/documents       # multipart
GET    /api/knowledge-bases/{id}/documents
GET    /api/knowledge-documents/{id}
GET    /api/knowledge-documents/{id}/file        # 鉴权代理，inline/attachment
GET    /api/knowledge-documents/{id}/chunks      # offset/limit
POST   /api/knowledge-documents/{id}/parse
POST   /api/knowledge-documents/{id}/delete
```

所有接口沿用 Cookie、CSRF、Origin 和 `X-Workspace-ID` 鉴权；`/file` 为浏览器新窗口导航，允许 `workspace_id` 查询参数，与 SSE 同例。

## 七、检索工具

```text
search_knowledge_base(query, kb_ids?, top_k?)
```

- 工具身份来自当前 Run，模型不能提交用户、空间或 RAGFlow dataset ID。
- 服务端把 `kb_ids` 与当前用户可访问知识库求交集。
- 单轮最多 `EA_KNOWLEDGE_MAX_CALLS_PER_RUN`（默认 3）次检索。
- 单次返回不超过 `EA_KNOWLEDGE_MAX_CONTEXT_CHARACTERS`（默认 8000）字符。
- 返回 `document_id`、`document_name`、`similarity`、`positions` 等应用侧来源。
- 子 Agent 与主 Agent 共用同一运行身份、配额和知识库范围。
- 详情页“检索测试”走独立服务方法：不写 tool_calls、不做上下文预算裁剪、阈值由用户指定。

## 十、已知限制与后续

1. **解析状态刷新是请求时同步**：打开文档列表或刷新时调用 RAGFlow；前端解析中每 5 秒轮询，没有后台 Worker。
2. **知识库配置变更不会自动重建已有索引**：新文档使用新配置；已有文档可用“应用到已有文档并重新解析”。
3. **embedding 模型首版不可修改**：需要重建知识库或后续引入索引版本。
4. **无文档级 ACL**：检索权限落在知识库/dataset 层。
5. **原文件预览依赖本地 MIME 判断**：HTML/SVG 强制 attachment，避免内联脚本；PDF/图片/文本依赖浏览器原生能力。
6. **单 RAGFlow 服务账号**：服务账号泄露会扩大影响面；建议内网隔离、密钥轮换，后续按空间拆团队/API Key。
7. **真实解析质量待评测**：当前真实验证使用 TXT；PDF、Word、Excel、扫描件需建立固定评测集。
8. **删除真实 dataset/document 未在真实实例验收**：客户端方法和单元契约已覆盖，但为避免误删用户数据未执行真实删除。
