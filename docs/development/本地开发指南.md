## 1. PostgreSQL

复用本机已有的 PostgreSQL Windows 服务，使用 postgres 用户。不新建实例，不执行 initdb。

- 已检测到的服务名：postgresql-x64-16。
- 连接地址示例：127.0.0.1:5432（默认端口，请以已有服务实际配置为准）。
- 登录用户：postgres，密码使用你已有的密码，项目不会修改该密码。
- 开发库：enterprise_agent；集成测试库：enterprise_agent_test，两库位于同一个已有服务中。

用户已启动现有服务，2026-11-03 已使用 postgres 用户成功创建开发库与测试库并验证连接。后续如服务停止，请通过 Windows 的“服务”应用启动 postgresql-x64-16；不要创建新服务或新实例。

在 Git Bash 中检查登录，按提示输入已有密码，不要把密码发到聊天里：

~~~bash
export PATH="/d/PostgreSQL/16/bin:$PATH"
psql -h 127.0.0.1 -p 5432 -U postgres -d postgres -W
~~~

登录后先查看数据库：

~~~sql
\l
~~~

仅当库不存在时，在 psql 中分别创建：

~~~sql
CREATE DATABASE enterprise_agent;
CREATE DATABASE enterprise_agent_test;
~~~

这只是在已有服务里创建数据库，不会新建 PostgreSQL 实例。已有同名库时不要重复创建；如果其中已有其他应用数据，先确认归属再执行迁移。

之前为本项目启动的 .local/postgres 实例（55432）已经停止，数据保留，不再作为启动步骤。其数据未自动复制到现有服务；此前仅有阶段一初始化标记，新的目标库需要执行迁移。

## 2. 配置与后端

从根目录复制配置样例；已有文件不会覆盖：

~~~bash
test -f backend/.env || cp backend/.env.example backend/.env
~~~

backend/.env 使用独立字段，修改密码和实际端口即可：

~~~dotenv
EA_ENVIRONMENT=development
EA_DATABASE_HOST=127.0.0.1
EA_DATABASE_PORT=5432
EA_DATABASE_USER=postgres
EA_DATABASE_PASSWORD='你的已有密码'
EA_DATABASE_NAME=enterprise_agent
EA_TEST_DATABASE_NAME=enterprise_agent_test
EA_CORS_ORIGINS=["http://localhost:8686","http://127.0.0.1:8686"]
EA_LOG_LEVEL=INFO
EA_DATABASE_TIMEOUT_SECONDS=3
~~~

密码填写原文，不需要 URL 编码；包含空格或 # 等字符时请加引号。若密码中有单引号，改用双引号包裹，并按 dotenv 语法转义内部引号或反斜杠。配置以 dotenv 语法解析。旧 EA_DATABASE_URL 已不再读取，请移除该旧配置项，改用上面的独立字段。然后执行：

~~~bash
cd backend
uv sync --frozen
uv run alembic upgrade head
uv run alembic current
uv run alembic check
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
~~~

当前迁移 head 为 0016。0013 及之前包含登录会话、对话、工具审计、定时问答、知识库、Agent 与审批；0014/0015 为集成配置和连接器；0016 为微信 iLink 渠道。就绪检查要求 schema_version=16。已有旧版数据库必须执行 upgrade head，否则就绪接口返回 SCHEMA_NOT_READY。详见 [阶段二数据模型](阶段二数据模型.md)、[定时问答任务](定时问答任务.md)、[知识库实现与验收](知识库实现与验收.md)、[Agent 工作台实现与验收](Agent工作台实现与验收.md) 和 [微信 iLink 渠道](微信iLink渠道.md)。

后端接口文档：http://127.0.0.1:8000/docs 。数据库迁移不在应用启动时自动运行，必须显式执行，避免未来多个进程同时迁移。

## 3. 前端

也可在项目根目录使用 Python 脚本同时启动前后端（脚本仅依赖 Python 标准库）：

~~~bash
python scripts/start.py
~~~

Python 脚本根据自身位置定位项目，支持从其他目录使用脚本绝对路径启动。先检测 8000 和 8686 端口，再执行 uv sync --frozen；缺少 node_modules 时自动执行 npm ci。前端依赖锁文件更新后请手动重新安装。随后同时启动后端 8000（含 reload）与前端 8686；按 Ctrl+C 或其中任一服务退出时，清理本脚本启动的前后端进程树。旧命令 python scripts/start_frontend.py 同样转为启动两端。

使用一键启动时不要再单独启动两端。PostgreSQL 必须预先运行，backend/.env、数据库迁移与管理员初始化仍按前文显式完成，脚本不自动迁移或创建账号。BAT 脚本仍仅启动前端。

2026-11-04 启动脚本验证：Ruff 与严格 mypy 通过；从项目外目录启动后，8000 存活接口和 8686 首页均返回 HTTP 200；触发 Python 中断后，两端端口均释放。此检查只验证启动与退出，不代表模型问答验收。

推荐双击 scripts/start-frontend.bat，或在项目根目录的 Windows 命令提示符中执行：

~~~bat
scripts\start-frontend.bat
~~~

BAT 脚本会自动定位 frontend，支持从任意目录启动；失败时保留窗口供查看错误。首次缺少 node_modules 时运行 npm ci，随后以前台方式启动，按 Ctrl+C 停止。依赖锁文件更新后请手动重新执行 npm ci。后端需单独启动；修改端口配置后请重启后端，让 CORS 和可信来源生效。

另开 Git Bash，在项目根目录执行：

~~~bash
cd frontend
npm ci
npm run dev
~~~

访问 http://127.0.0.1:8686/ 。Vite 将 /api 代理到 http://127.0.0.1:8000 ，因此前后端需要同时运行。端口 8686 被占用时启动会失败，不会静默切换到其他端口。

VITE_API_BASE_URL 默认空值，使用同域代理。需要直接访问其他本机 API 地址时，可参考 frontend/.env.example；VITE_ 变量会进入浏览器构建产物，不能存密钥。

## 5. 常见问题

- API 正常、数据库未就绪：检查数据库实例、端口、凭证，再执行 alembic upgrade head；使用响应中的 request_id 查找后端日志。
- 前端无法连接后端：确认 8000 端口服务正常、Vite 代理目标未修改。
- 端口与服务不符：检查已有 PostgreSQL 服务的实际端口，仅修改 EA_DATABASE_HOST / EA_DATABASE_PORT 等独立配置，不为项目另建实例。
- Windows 异步驱动错误：当前固定使用 asyncpg；更换驱动前必须验证事件循环兼容性。
- 依赖变更：有意更新依赖后提交对应锁文件；日常使用 uv sync --frozen 与 npm ci。

### Windows 启动报 WinError 10013

本项目曾确认由旧 Uvicorn 占用 127.0.0.1:8000 导致。先检查端口占用和 Windows 端口保留范围：

~~~bash
netstat.exe -ano | findstr.exe ":8000"
netsh.exe interface ipv4 show excludedportrange protocol=tcp
~~~

若已有本项目后端，优先回到旧终端按 Ctrl+C 停止，再启动新后端。需要结束后台进程时，先确认 PID 对应本项目 Uvicorn；不要批量结束所有 Python 进程。若端口没有占用但位于保留范围，另选可用端口并同步调整 Vite 的 /api 代理目标。

## 7. 手工验证问答

1. 更新依赖并迁移：在 backend 执行 uv sync --frozen、uv run alembic upgrade head。
2. 确认 backend/.env 的 EA_DEEPSEEK_API_KEY 已填写。停止旧后端再按第 2 节重启；旧进程可能没有新接口或仍使用旧配置。
3. 在 frontend 执行 npm ci、npm run dev，打开 http://127.0.0.1:8686/chat。
4. 发送“记住代号 TEST-123，只回复收到”，再问“刚才的代号是什么”，验证连续追问。
5. 刷新页面检查消息；执行中点击“停止生成”，检查状态为已停止、子任务收敛。正文按成功模型动作完整发布，失败尝试不展示半段内容；已提交内容保留。回答中的 Markdown 表格、列表和代码块应按格式渲染，原始 HTML 会被安全清洗。
6. 生成中刷新或切换对话，重新打开原对话，应继续显示最新内容。
7. 系统状态页面位于 /system；问答 OpenAPI 在 http://127.0.0.1:8000/docs。

真实模型独立验收（会产生两次短模型调用，使用已有专用测试库并清理本次记录；不要与数据库迁移测试并行执行）：

在问答页面 /chat 输入目标，复杂请求由主 Agent 按需规划、执行并汇总；计划与子 Agent 状态直接展示在消息下方。侧边栏不提供独立“计划与执行”，旧 /tasks 地址回到问答；无需编辑 JSON 或确认每个只读步骤。

示例：“先列工作计划，再并行委派分析员和复核员分析企业 Agent 本地开发方案，最后总结。”也可以要求查询本人运行统计后分析。没有联网或文件能力；企业资料检索通过知识库工具完成，需要配置 RAGFlow。

默认同一问答最多两个子 Agent 并行，最多六个子任务，禁止递归委派。子 Agent 共享本次运行的可信身份和统计查询配额，每个查询独立数据库会话。执行中输入补充要求可点击“停止并补充要求”；失败/取消可点击“重试本次请求”，均在原对话中产生新 Run、保留旧记录。

单模型请求失败复用 EA_TASK_RETRY_ATTEMPTS/BASE_SECONDS/MAX_SECONDS/MAX_WAIT_SECONDS，默认总共 3 次；SDK 重试关闭。429 的有效 Retry-After 优先，超长等待明确失败，用户稍后重试。EA_MODEL_TIMEOUT_SECONDS 为单请求上限，EA_CHAT_RUN_TIMEOUT_SECONDS 为整轮含等待上限。成功步骤不会因后续模型请求重试而重复执行；手工重试创建新运行，不能保证旧工具不会再查。

状态和结果保存在现有 tool_calls 下，不新增迁移或服务。SSE 发布回复快照，执行记录在展开时轮询；正文按完整成功模型动作发布。关闭页面不停止生成，退出登录关闭订阅但不取消合法后台运行；服务重启中断对话运行，不支持任意图节点续跑。旧独立 Task 后端保留兼容，原动作检查点说明见 [旧任务接口](规划执行实现与接口.md)。

真实验收（调用付费模型，仅使用已有测试库，精确清理临时资料；不要与数据库迁移测试同时运行）：

~~~bash
cd backend
uv run python -m scripts.verify_real_chat_agents
~~~

详细架构、记录格式、配额及验收见 [对话内规划与子 Agent](对话内规划与子Agent实施.md)。

## 13. 定时问答

已实现 Cron 定时问答。先登录并打开 /schedules，选择已有对话或点击“新建对话”，用执行时间构建器选择每天、每周、每月或固定间隔（也可切换高级 Cron），填写 IANA 时区和问题；保存后到期会自动在该固定对话中创建一个新的问答 Run，复用现有规划、工具和子 Agent。

- 示例：`0 9 * * *` 每天 09:00；`*/30 * * * *` 每 30 分钟；`0 9 * * 1-5` 工作日 09:00。
- 同一对话已有运行生成时，本次触发记录为 skipped，不会排队重放；错过的多次触发只保留最近一次，不补跑积压。
- 支持停用、编辑、删除和“运行一次”；手工运行不改变原定 Cron 的下一次时间。
- 任务只属于创建者和当前空间，管理员也不能查看或修改他人的定时任务。
- 服务重启后已提交的运行按现有问答规则收敛；调度器继续处理后续触发。

配置、接口、权限和验收见 [定时问答任务](定时问答任务.md)。修改代码后执行 `uv run alembic upgrade head`，再重启后端；调度器与问答执行器都要求单进程运行。

## 14. 知识库

知识库使用本地 RAGFlow 1.0 作为解析与检索底座。应用侧 PostgreSQL 保存知识库、文档、解析状态和权限；前端不直接访问 RAGFlow。

1. 在 `backend/.env` 配置 `EA_RAGFLOW_BASE_URL` 和 `EA_RAGFLOW_API_KEY`。未配置密钥时知识库 API 返回未配置错误，知识库工具不会注册。
2. 执行 `uv run alembic upgrade head`（迁移 0013）并重启后端。
3. 打开 `/knowledge`。空间管理员可创建空间知识库，普通成员可创建私有知识库。
4. 创建时可选解析模板；进入 `/knowledge/:id` 详情页后有三个 Tab：
   - 文档管理：多文件上传、解析进度/失败原因、查看原文、查看分块、可配置重新解析、删除；解析中每 5 秒自动刷新。
   - 解析配置：preset 模板、parser_id、分块参数、PDF 解析方式、自动关键词/问题；保存后可“应用到已有文档并重新解析”。
   - 检索测试：直接输入问题、调 top_k/阈值，查看命中内容、来源和相似度。
5. 只有 `ready` 文档可检索。问答中主 Agent 和子 Agent 都可以调用 `search_knowledge_base`，来源显示在工具调用记录中。
6. 管理员不能读取他人的私有知识库；成员只能管理自己有权限的知识库。

原文件预览通过新窗口打开 `/api/knowledge-documents/{id}/file?workspace_id=...`，由后端代理鉴权；PDF/图片/纯文本内联展示，HTML/SVG 等强制下载。RAGFlow 1.0 的创建/更新 dataset、文档 PATCH、下载和分块参数与公开旧文档不同；新增或升级 RAGFlow 版本时必须先跑契约测试。完整实现、权限规则和验收见 [知识库实现与验收](知识库实现与验收.md)。
