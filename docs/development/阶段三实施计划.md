# 阶段三实施计划：身份与数据隔离

日期：2026-11-03。当前状态：本地登录、归属隔离和接口鉴权已实现，自动化验收通过；等待本机管理员初始化与浏览器手工验收。

## 目标

让现有问答工作台支持可信用户身份及工作空间隔离，覆盖历史、摘要、创建运行、查询、取消和 SSE 的全部入口。普通问答仍不创建任务，不引入预算输入。

## 已选技术方向

- 账号：首版内置账号，不开放自助注册。3.2 提供显式初始化命令，初始密码由本机操作者输入，不预设通用默认密码，不把账号明文凭证写入迁移。
- 密码：使用成熟组件生成和验证 Argon2id 编码哈希。3.1 仅建立存储结构与格式检查，不实现哈希算法。
- 登录态：采用服务端会话与 HttpOnly Cookie，随机不透明令牌，数据库只保存会话令牌摘要；会话表和逻辑已在 0005 增加。优先保证退出、账号禁用和撤权可以立即在服务端生效。
- 请求保护：前端继续使用同源 /api 代理；状态修改接口实现来源与 CSRF 校验，不能只依赖隐藏按钮或 SameSite。会话过期不由浏览器自行决定。
- 角色：固定 admin / member，属于工作空间成员关系；不引入全局超级用户字段、自定义角色表或权限表达式。
- 资源：首版对话默认私有。空间管理员管理空间和成员，但不会自动获得阅读他人对话的权限。后续共享对话需要独立设计授权规则。

取舍：服务端会话相比纯无状态 JWT 增加数据库查询，但便于当前单体架构实现撤销和一致鉴权；JWT 对分布式场景的优势暂时不需要。固定双角色更容易验证；代价是后续自定义授权需要另行扩展。

## 后续接口与权限收口

已实现 POST /api/auth/login、POST /api/auth/logout、GET /api/auth/me；GET /api/auth/me 同时返回会话绑定的 CSRF 值，写操作检查 Origin 和 CSRF。

工作空间作为请求上下文由受信服务根据会话与成员记录验证。客户端可以选择 workspace_id，但不能用请求里的 user_id 或模型参数冒充身份。对话的空间与创建者由服务端绑定。

业务查询、取消和订阅均通过 Conversation 归属进行鉴权；Message、Run 和持久化摘要继承对话的隔离边界，避免引入相互不一致的所有者字段。旧接口必须同时加鉴权或移除，不能留下可绕过新入口的兼容路径。

SSE 不能只在连接建立时校验一次；订阅期间需检查会话过期、退出、账号禁用和成员撤销，并停止继续发送内容。撤权后的生成处理与重新订阅都须遵循同一资源规则，不能因为运行已经开始而扩大权限。

## 旧数据迁移策略

3.1 的 0004 只新增身份基础表，不修改现有对话，不自动猜测归属。

3.3 已采用成对可空归属字段与成员复合外键，无归属历史保持隐藏；由本机命令在显式选定的初始账号/空间下认领，不强制未认领旧记录立即非空。认领命令须拒绝错误空间和非成员账号，可重入且不覆盖已经有归属的数据。认领前后的消息、Run 状态、摘要、游标和版本必须一致。

当前 0005 已启用身份隔离。旧记录以成对 NULL 归属安全隐藏，显式认领后开放给指定管理员；因此暂不强制所有历史记录立即非空，具体取舍见登录与接口鉴权文档。
