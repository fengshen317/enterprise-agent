# 后台用户与角色管理

固定角色为 admin/member。成员密码流程依赖迁移 `0028`，就绪接口检查的版本为 `28`。

## 产品入口与操作

管理员登录后，侧边栏出现“后台管理”，地址 http://127.0.0.1:8686/admin/members。管理范围始终是顶部选中的工作空间，切换空间会卸载旧页面并清理表单及请求结果。

- 查看、搜索、分页列出当前空间的成员（含停用成员）。
- 创建全新账号，填写登录名、显示名与空间角色，系统为新账号使用部署的统一初始密码。
- 系统管理员可从「成员与权限 → 设置初始密码」进入配置表单，也可直接从「API 配置」找到「统一初始密码」。输入两次新密码后保存，后续新建和重置立即使用新值。
- 修改当前空间成员角色；停用/恢复成员访问，保留成员关系及历史归属。
- 在成员行选择“重置密码”并确认，目标账号的旧会话随即失效。成员使用统一初始密码再次登录后，需设置个人密码。
- 查看当前空间的管理操作记录。
- 已登录用户可从侧栏账户区选择“修改密码”，输入当前密码和两次新密码。保存成功后使用新密码重新登录。

新建和重置优先使用系统管理员在前端保存的统一初始密码。该值复用部署配置的加密存储和 `EA_INTEGRATION_CONFIG_KEY_FILE`，随 API 重启恢复，前端只收到配置状态和更新记录。未在前端设置时，使用部署 `.env` 中的 `EA_MEMBER_INITIAL_PASSWORD`（本机开发为 `backend/.env`）。两处均未设置时，首次新建或重置会随机生成，写入 API 用户主目录的 `.enterprise-agent/member-initial-password`，之后复用。Compose 的 `api_home` 卷保存生成文件和默认加密密钥文件。可通过 `EA_MEMBER_INITIAL_PASSWORD_FILE` 指定生成密码的持久路径。

统一初始密码支持 8 至 128 个字符，保留首尾字符，至少包含一个非空白字符。仍使用自动生成的密码时，部署管理员可在服务器部署目录执行 `docker compose exec api cat /home/enterprise-agent/.enterprise-agent/member-initial-password`。此前开通的账号按各自已经写入的哈希验证，需重新发放时由管理员显式重置。

个人新密码需为 8 至 128 个字符，至少包含一个非空白字符，并区别于当前密码和统一初始密码。输入按原文处理。数据库给每个账号分别生成带独立盐的 Argon2id 哈希。接口响应、审计和前端持久存储不保存明文。重复账号返回 `ACCOUNT_EXISTS`，按原凭证验证。首次部署管理员使用独立初始化入口设置个人密码。

## 权限矩阵

|能力|空间管理员|普通成员|
|---|---|---|
|本人私有问答与只读工具|可以|可以|
|查看他人私有对话/工具记录|不可以|不可以|
|当前空间成员查询与管理|可以|不可以|
|当前空间管理审计|可以|不可以|
|修改个人密码|可以|可以|
|设置部署级统一初始密码|需要系统管理员权限|需要系统管理员权限|
|重置当前空间其他成员的密码|仅限目标账号和该空间成员关系均已启用，且目标只属于当前空间|不可以|
|管理其他空间的成员|需要在该空间也拥有有效管理员角色|不可以|
|禁用全局账号/影响其他空间成员关系|本版本不提供|不可以|

前端隐藏入口并刷新身份，但真正授权在服务端：active 用户、active 空间、active 成员关系、role=admin。每次管理请求检查角色；业务问答继续按对话所有者过滤。请求中的空间选择不能代替成员授权。

密码用于全局账号认证。网页重置保护首个系统管理员、部署指定的系统管理员和具有其他空间成员记录的用户，包含其他空间已停用的记录。受保护账号可由本人改密，或由部署管理员通过本机账号命令重置。工作空间管理员在列表中重置其他成员时，服务端复核这些条件。

## API

沿用 Cookie 会话与 X-Workspace-ID。所有 POST 要求受信 Origin 和 X-CSRF-Token；读取管理列表与审计响应 no-store。

|接口|用途|
|---|---|
|GET /api/admin/members?offset=0&limit=20&q=关键词|当前空间成员页，limit 1–100，搜索账号/显示名，字面匹配通配符|
|POST /api/admin/members|创建用户，字段为 username、display_name、role（默认 member）|
|POST /api/admin/members/{user_id}|修改角色/状态；必须提供 role=admin/member 和 status=active/revoked|
|POST /api/admin/members/{user_id}/reset-password|重置他人密码为部署统一初始密码，成功返回 204|
|POST /api/auth/change-password|本人改密，字段为 current_password、new_password，成功返回 204|
|GET /api/admin/configs、POST /api/admin/configs|系统管理员读取 `member_initial_password` 的掩码状态或保存新值，保存即时生效|
|GET /api/admin/audits?offset=0&limit=20|分页读取当前空间管理操作，最新在前|

用户创建响应与成员列表包含 user_id、username、display_name、user_status、role、status、joined_at、updated_at。user_status 只读；停用操作修改的是成员 status，不修改 User.status。

创建请求提交 `password` 等额外字段时返回 422。无会话返回 401，非空间管理员返回 `ADMIN_REQUIRED`（403），当前空间找不到目标返回 `MEMBER_NOT_FOUND`（404）。禁止重置自己的密码、停用成员或受保护账号时返回 409。归档空间拒绝管理写入。

## 事务、并发与失效

新建账号前先检查管理员，再在线程生成哈希。写入事务取得与 CLI 相同的全局账号锁，再锁定当前 Workspace 行，重新检查管理员，原子提交用户、成员与管理审计。重复/并发创建不能覆盖已有账号或留下半份审计。

修改角色/成员状态先锁当前 Workspace，再重新检查操作者与目标成员。该空间的管理写入串行化，避免两个管理员并发把所有有效管理员降级或停用。有效管理员计数包含 User.active、Membership.active、role=admin；至少保留一人。

对相同角色/状态重复保存视为幂等无变更，不重复记审计。自己降级时，前端重新取会话并退出管理页。管理员撤权后旧 Cookie 不会保留管理权限；同一用户其他空间角色不受影响。

停用成员后，旧会话可以继续登录及访问其他有效空间，但不能访问被停用空间。已有 SSE 和后台生成沿既有动态撤权规则收敛；恢复关系后可以再次访问原私有历史。角色从管理员变普通成员只影响管理能力，不停止其正常私有问答。

网页新建或重置时置 `users.must_change_password` 为真。此时会话只可恢复登录状态、本人改密和退出，访问受保护业务接口返回 `PASSWORD_CHANGE_REQUIRED`（403）。本人改密、网页重置和本机重置更新 Argon2id 哈希并递增 `session_version`，使此前全部浏览器会话失效。本人改密和本机重置同时清除改密标记。本人改密提交前复核当前会话和原密码哈希，防止并发请求用旧验证结果覆盖新密码。

这些一致性规则约束网络管理服务；受信本机数据库操作者仍可直接修改数据库，不把本机数据库权限视为低权限入口。

## 数据模型与迁移

0007 仅增加 admin_audits，不修改原角色结构。字段：workspace_id、actor_user_id、target_user_id、actor_username、target_username、action、before_role、before_status、after_role、after_status、created_at、id。

审计和实际变更同事务，保存操作人、目标账号和角色/成员状态快照。`action` 为 `create_user`、`update_member` 或 `reset_password`。操作者/目标 ID 为审计快照，不引用可变成员关系。空间外键级联清理受信物理删除空间时的记录。

`0028` 添加改密标记，已有账号默认关闭并保留原密码。升级运行 `uv run alembic upgrade head`，Compose 镜像启动时自动执行。仍有待改密账号时迁移拒绝回退，以免旧版 API 直接放行共享初始密码会话。

## 测试与验收

真实 PostgreSQL 和 HTTP 登录用例覆盖统一初始密码、独立哈希、业务接口拦截、旧账号空密码兼容、并发改密、管理员重置授权及审计、会话失效、角色和停用行为、并发创建与最后管理员保护、CSRF 和 Origin 校验。

统一初始密码配置用例覆盖系统管理员授权、无效密码拒绝、密文持久化、重载，以及新值立即用于新建和重置。Vue 测试覆盖密码确认、掩码、创建表单、重置确认和取消、角色和状态保存、改密后的会话清理、自降级跳转和搜索。完整检查命令为 `node scripts/check.mjs --database`。

本地 Chrome 使用独立 PostgreSQL 测试库验证了管理员创建成员、首次改密、主动改密、取消与确认重置及旧会话失效。390 像素宽视口下，设置入口能定位到表单，保存后新成员可使用新密码登录，设置和改密页面无横向溢出。前端配置功能的生产部署尚未验收。原成员权限验收见 [后台管理验收记录](后台管理验收记录.md)。
