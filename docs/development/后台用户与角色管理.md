# 后台用户与角色管理

日期：2026-11-04。按用户确认采用固定 admin/member，不实现自定义角色或细粒度权限配置。当前迁移 head=0007，健康标记 7。

## 产品入口与操作

管理员登录后，侧边栏出现“后台管理”，地址 http://127.0.0.1:8686/admin/members。管理范围始终是顶部选中的工作空间，切换空间会卸载旧页面并清理表单及请求结果。

- 查看、搜索、分页列出当前空间的成员（含停用成员）。
- 创建全新账号，设置登录名、显示名、初始密码和 admin/member 角色，并加入当前空间。
- 修改当前空间成员角色；停用/恢复成员访问，保留成员关系及历史归属。
- 查看当前空间的管理操作记录。

按照本项目现有密码偏好，初始密码输入明文可见，不限制长度或字符组成，允许空字符串；不裁剪用户输入。成功后清空表单，密码不进入审计、响应、localStorage 或日志，数据库继续保存 Argon2id 哈希。

同名账号返回 409，不覆盖其密码，不自动接管或加入其他空间的现有账号。初始管理员仍通过受信本机 CLI 创建。本版本不提供已有账号邀请、全局账号禁用、网页重置密码、修改全局显示名、自助注册、空间管理或自定义权限；这些需要单独定义跨空间授权边界。

## 权限矩阵

|能力|空间管理员|普通成员|
|---|---|---|
|本人私有问答与只读工具|可以|可以|
|查看他人私有对话/工具记录|不可以|不可以|
|当前空间成员查询与管理|可以|不可以|
|当前空间管理审计|可以|不可以|
|管理其他空间的成员|需要在该空间也拥有有效管理员角色|不可以|
|禁用全局账号/影响其他空间成员关系|本版本不提供|不可以|

前端隐藏入口并刷新身份，但真正授权在服务端：active 用户、active 空间、active 成员关系、role=admin。每次管理请求检查角色；业务问答继续按对话所有者过滤。请求中的空间选择不能代替成员授权。

## API

沿用 Cookie 会话与 X-Workspace-ID。所有 POST 要求受信 Origin 和 X-CSRF-Token；读取管理列表与审计响应 no-store。

|接口|用途|
|---|---|
|GET /api/admin/members?offset=0&limit=20&q=关键词|当前空间成员页，limit 1–100，搜索账号/显示名，字面匹配通配符|
|POST /api/admin/members|创建用户；username、display_name、password、role（默认 member）|
|POST /api/admin/members/{user_id}|修改角色/状态；必须提供 role=admin/member 和 status=active/revoked|
|GET /api/admin/audits?offset=0&limit=20|分页读取当前空间管理操作，最新在前|

用户创建响应与成员列表包含 user_id、username、display_name、user_status、role、status、joined_at、updated_at。user_status 只读；停用操作修改的是成员 status，不修改 User.status。

禁止在创建/更新正文添加 workspace_id、user_id、全局状态、密码重置等字段，额外字段 422。无登录 401；非管理员 ADMIN_REQUIRED/403；跨空间目标 MEMBER_NOT_FOUND/404；账号重复 ACCOUNT_EXISTS/409；最后管理员 LAST_ADMIN_REQUIRED/409；空间归档后拒绝管理。

## 事务、并发与失效

新建账号前先检查管理员，再在线程生成哈希。写入事务取得与 CLI 相同的全局账号锁，再锁定当前 Workspace 行，重新检查管理员，原子提交用户、成员与管理审计。重复/并发创建不能覆盖已有账号或留下半份审计。

修改角色/成员状态先锁当前 Workspace，再重新检查操作者与目标成员。该空间的管理写入串行化，避免两个管理员并发把所有有效管理员降级或停用。有效管理员计数包含 User.active、Membership.active、role=admin；至少保留一人。

对相同角色/状态重复保存视为幂等无变更，不重复记审计。自己降级时，前端重新取会话并退出管理页。管理员撤权后旧 Cookie 不会保留管理权限；同一用户其他空间角色不受影响。

停用成员后，旧会话可以继续登录及访问其他有效空间，但不能访问被停用空间。已有 SSE 和后台生成沿既有动态撤权规则收敛；恢复关系后可以再次访问原私有历史。角色从管理员变普通成员只影响管理能力，不停止其正常私有问答。

这些一致性规则约束网络管理服务；受信本机数据库操作者仍可直接修改数据库，不把本机数据库权限视为低权限入口。

## 数据模型与迁移

0007 仅增加 admin_audits，不修改原角色结构。字段：workspace_id、actor_user_id、target_user_id、actor_username、target_username、action、before_role、before_status、after_role、after_status、created_at、id。

审计和实际变更同事务；只保存角色/成员状态及操作人快照，不保存凭证。action=create_user/update_member。操作者/目标 ID 为审计快照，不引用可变成员关系；空间外键级联清理受信物理删除空间时的记录。现阶段不提供网络删除空间或删除审计接口。

开发库只向前升级。测试库迁移往返包括 0007；降级会丢失操作审计，但不会撤销已执行的成员变化，不作为常规回滚方式。
