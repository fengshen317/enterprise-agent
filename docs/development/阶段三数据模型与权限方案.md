# 阶段三数据模型与权限方案

日期：2026-11-03。当前 head：0005；本文记录 0004 的用户、空间、成员模型。登录、会话与问答鉴权现已接入，新增表及接口见 [登录与接口鉴权](登录与接口鉴权.md)。

## 关系与边界

User 与 Workspace 通过 WorkspaceMembership 建立多对多关系。一名用户可以在空间甲是管理员，在空间乙是普通成员。角色不放在 User，也不单独创建动态角色配置表。

这些是应用业务表，不是 PostgreSQL 数据库用户。继续使用现有服务、postgres 数据库账号与原开发/测试库；本次不改连接配置、不创建实例。

## users

|字段|类型|含义|
|---|---|---|
|id|UUID PK|应用用户标识，应用生成|
|username|varchar(64)，全局唯一|规范化小写登录名，3–64 字符，首字符字母或数字，余下可用数字、小写字母、下划线、点、短横线|
|display_name|varchar(100)|可显示中文，不允许仅为空白|
|password_hash|text|Argon2id 编码哈希，无默认值，不能省略|
|status|varchar(16)|active / disabled，默认 active|
|session_version|integer|默认 1，必须大于 0，为后续全量会话失效预留版本|
|password_changed_at|timestamptz|默认 now()，后续更改密码时显式更新|
|created_at / updated_at|timestamptz|默认 now()，后续服务负责维护 updated_at|

登录服务在 3.2 规范化输入；数据库目前直接拒绝大写或不规范 username，唯一约束保证规范化后的账号不重复。显示名与登录名分开。

password_hash 检查只验证 $argon2id$ 前缀和最低长度，防止普通明文直接写入；它不验证真实密码学哈希是否有效。真正的哈希生成、参数校验、常量时间安全校验及登录错误处理由 3.2 的成熟组件实现，不能用该 CHECK 代替登录验证。测试中的哈希形状占位值不是真实可登录凭证。

## workspaces

|字段|类型|含义|
|---|---|---|
|id|UUID PK|稳定资源边界|
|slug|varchar(64)，唯一|3–64 字符，小写字母/数字/短横线，首尾必须字母或数字|
|name|varchar(100)|空间显示名称，不允许仅为空白|
|created_by_user_id|UUID FK → users.id|创建者审计，不自动代表当前管理权限|
|status|varchar(16)|active / archived，默认 active|
|created_at / updated_at|timestamptz|创建与最后更新时间|

索引 created_by_user_id。授权以实时成员关系为准，不把创建者字段当作绕过成员校验的入口。创建空间的后续服务应在同一事务内创建空间及创建者的 admin 成员关系。

## workspace_memberships

|字段|类型|含义|
|---|---|---|
|workspace_id|UUID FK → workspaces.id|联合主键第一部分|
|user_id|UUID FK → users.id|联合主键第二部分|
|role|varchar(16)|admin / member，默认 member|
|status|varchar(16)|active / revoked，默认 active|
|created_at / updated_at|timestamptz|建立与最后变更时间|

联合主键保证同一用户在同一空间最多一条成员关系。反向索引 (user_id, status, workspace_id) 支持查询用户可用空间。撤销保留成员记录，恢复通过更新原记录完成，不能重复插入另一条记录。

所有外键使用默认限制删除行为，不级联清空用户、空间或成员。已有依赖关系时直接删除会被拒绝；首版使用禁用、归档、撤销管理生命周期。

## 权限矩阵（私有问答已接入，网络管理接口尚未实现）

所有操作都先要求账号有效、会话有效且为目标空间的 active 成员。

|操作|普通成员|空间管理员|
|---|---|---|
|查看所在空间及自己的成员关系|允许|允许|
|新建对话、发送问题|活跃空间允许|活跃空间允许|
|读取自己的对话、消息、摘要和运行状态|允许|允许|
|停止自己的运行、订阅自己的 SSE|允许|允许|
|读取、停止或订阅其他人的私有对话|拒绝|拒绝|
|修改空间信息、管理成员和角色|拒绝|按管理接口校验允许|
|归档/恢复空间|拒绝|按管理接口校验允许|
|跨空间访问非成员资源|拒绝|拒绝|

归档空间不允许新建和发送，仍允许读取自己的历史及停止自己的运行。disabled 用户或 revoked 成员不能继续访问资源。管理员管理成员不等于读取成员聊天内容。

后续成员服务修改角色或撤销成员时应锁定空间行，避免并发操作移除最后一个有效管理员。这个规则涉及多行状态，3.1 的 CHECK/FK 不负责保证；当前不提供网络成员管理 API，不能宣称已经完成最后管理员规则的管理接口验证。

## 初始账号与历史记录

0004 不插入默认用户、不写默认密码、不自动赋予管理员权限。初始账号与空间在 3.2 通过显式初始化流程建立，3.3 再迁移无归属的历史对话。现有聊天与摘要不因本次迁移改变。

后续身份上下文由后台根据会话确定，不接受前端直接指定可信 user_id。Conversation 增加空间和创建者归属后，Message、Run、摘要都从对话继承边界；前端隐藏内容不能代替后端查询过滤。

## 迁移与验证

在 backend 目录执行：

~~~bash
uv run alembic upgrade head
uv run alembic current
uv run alembic check
~~~

0004 新增三张表并将 system_metadata.schema_version 升为 4。当前健康检查要求 5；旧版本返回 SCHEMA_NOT_READY。0004 降级到 0003 会删除身份表数据，但不会删除或修改对话、消息、运行及摘要，仅在专用可丢弃测试库自动验证。

真实 PostgreSQL 集成测试验证 22 类非法写入、同用户跨空间不同角色、成员撤销状态、默认值及 0004 → 0003 → 0004 往返。往返后既有问题、回答、运行状态、摘要内容、游标和版本保持不变。测试数据以事务回滚或明确 ID 清理，不调用模型 API。
