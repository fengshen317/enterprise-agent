# 规划执行实现与接口

> 2026-11-05 产品方向已调整为对话内规划与子 Agent。本文独立 Task 的设计/接口作为历史与后端兼容参考；不再提供独立前端入口。当前能力和恢复边界以 [对话内规划与子 Agent](对话内规划与子Agent实施.md) 为准。

日期：2026-11-04。实现基线：0008 任务、计划、动作账本与事件迁移。自动化结果见 [规划执行验收记录](规划执行验收记录.md)。原始设计见 [Agent 规划、执行与网络重试设计](Agent规划执行与网络重试设计.md)。本文描述实际代码，不把设计中尚未实现的能力当成交付。

## 1. 已实现范围及设计差异

普通问答继续使用 Conversation/Message/Run；任务必须由用户显式创建。任务入口为 /tasks 或 /tasks/{task_id}，不增加预算填写，也不依赖 MCP、Redis 或 Celery。

当前任务执行方式是“计划中的单一动作逐步执行”：analysis/synthesis 步骤调用一次模型，tool 步骤执行确认后的一个只读工具。**步骤内部没有隐藏的多轮 ReAct、任意工具选择、子 Agent 或动态改写计划。**这比原设计的步骤内有限 ReAct 更严格，适合先验证状态、重试与恢复。

任务模型使用 Deep Agents 图完成计划和单步生成，但将工具选择列表置空；get_my_run_stats 由业务执行器直接调用共用只读服务。模型不能通过图的内置文件工具或 task 工具绕过计划。工具身份由任务的 owner_user_id/workspace_id 绑定。

已实现的检查点是 **TaskAction 成功结果与 ActionAttempt 终态同事务保存的应用级动作检查点**，不是 LangGraph 内部节点 checkpoint/checkpointer。它能覆盖“模型或工具结果已保存，步骤尚未标记成功”时的恢复窗口；不承诺在一次未完成模型请求的 token 或内部图节点处续跑。

任务结果按完整动作提交后展示，不推送任务模型逐 token 正文。因此失败请求的部分文本不会与新尝试拼接。原问答的 token 流式行为保持不变。

手动重试创建新的 TaskRun，重新规划并等待用户确认，**不自动复用旧执行中的统计和步骤结果**。旧执行记录仍可查询；同一个 TaskRun 内的网络重试或调度器重启，会复用已成功的动作结果。

## 2. 执行流程与完成条件

~~~mermaid
flowchart TD
    A[显式创建任务] --> B[生成并校验计划]
    B --> C[用户确认执行与计划版本]
    C --> D[选择依赖已完成的步骤]
    D --> E[模型动作或只读工具动作]
    E --> F[事务提交动作结果与尝试终态]
    F --> G[提交步骤成功及进度事件]
    G --> H{全部步骤成功?}
    H -->|否| D
    H -->|是| I[拼接叶子步骤结果并完成任务]
    E --> J{可重试?}
    J -->|是且次数时间允许| K[持久化等待]
    K --> E
    J -->|否或耗尽| L[失败并保留已完成结果]
~~~

计划步骤包含 key、title、kind、depends_on、instruction、tool_name、arguments。服务端验证：1–8 步、标识唯一、依赖存在且无环、标题非空；tool 只允许 get_my_run_stats，参数仅允许严格整数 days=1–90；analysis/synthesis 禁止携带工具和执行参数。未知身份字段不能进入计划。

计划保存为不可变 TaskPlan，按标准化 JSON 计算 SHA-256 摘要。每次修订新增版本，最多 3 个版本（初版加两次修订）；确认后不能原地编辑。模型通常会规划最后的 synthesis，但数据契约不强制必须有专门汇总步骤；最终输出由没有下游依赖的叶子步骤结果拼接，不额外隐式调用一次模型。

完成条件分层：模型必须返回完整非空文本，拒绝工具调用、输出截断和超过输出上限；工具结果由真实只读查询返回；所有必要步骤成功后，TaskRun 才能完成。文字“我已完成”不代替业务状态。分析内容的语义正确性尚需后续评测，不等同于数据库状态校验通过。

Task 归属复合外键关联 WorkspaceMembership，撤销关系不删除历史。Task.current_run_id 通过可延迟复合外键保证指向同一任务的 Run；允许同一事务先创建 Task，再创建 TaskRun。Step/Plan/Action 复合外键保证 task_id/run_id 一致。任务内部记录级联清理受信物理删除 Task 时的临时数据；当前不提供网络删除任务接口。

数据库还校验：合法状态、正数版本/尝试序号/事件序号、非负计数、租约 owner/expiry 成对出现、终态时间与状态一致、成功 Step/Action 必须有结果且非成功不能伪装持有成功结果。约束由真实 PostgreSQL 保存点测试验证，不仅依赖 Python。

## 4. 状态、暂停和取消

TaskRun：pending、planning、awaiting_confirmation、running、retry_wait、paused、completed、failed、cancelled。TaskStep：pending、running、retry_wait、paused、succeeded、failed、cancelled、skipped。

- pending/planning：生成计划；工具尚未执行。
- awaiting_confirmation：停在用户确认处，没有执行租约，不自动开始工具。
- running：执行就绪步骤，或并行时至少仍有活跃分支。
- retry_wait：请求失败已记录，next_retry_at 是持久化的最早重试时间。
- paused：用户暂停或供应商要求长等待；不会由后台自动继续。
- completed/failed/cancelled：本轮终态，旧历史不覆盖。

创建时规划总时限为 300 秒；保存草案后停止规划时钟。确认时开启 1800 秒执行时限，等待和暂停不重置该截止时间。恢复前检查截止时间，过期改为失败。

pause/cancel 控制先在数据库提交状态、递增 fencing_token 并释放租约，再取消本进程飞行请求；未完成步骤与尝试同步收敛，已成功结果保留。中断本地请求时还比较 run_id 与旧 token，避免迟到的暂停/取消请求误杀刚恢复的新执行。resume 恢复同一 TaskRun；长 Retry-After 仍未到期时，恢复回等待，不会提前发请求。retry 只允许失败或取消的执行，创建新 TaskRun 并重新规划。

所有控制必须提交最新 run_id/version；进度事件也会改变 version，旧页面的控制可返回 409，客户端需读取新快照后重新决定。取消与完成竞争由同一任务行锁确定，不能保证对已经完成的事务“追溯取消”。关闭网络连接也不能承诺供应商一定停止计算或不收费。

## 5. 网络重试与请求计数

自动重试只针对一个逻辑 TaskAction。真实请求每次新增 TaskActionAttempt；成功动作直接读结果，禁止再次发出外部请求。永久失败的动作也保留失败分类和最后一次尝试错误，恢复时直接沿用失败决策，不因为 TaskRun 尚未来得及收敛就重新发请求。数据库中 attempt_count 参与上限校验，进程重启不能清空计数。

|故障|当前策略|
|---|---|
|连接/读取超时、临时 Connect/Read/Write/Protocol 故障|允许有限重试|
|HTTP 408、429、500、502、503、504|作为重试候选，再检查供应商永久错误码|
|已识别的余额/额度/账号停用、401/403|不自动重试|
|参数/权限错误、未知应用或未知传输错误|默认不自动重试|
|已识别证书校验和确定不存在域名错误|不循环等待|
|数据库持久化异常|不当作模型故障重放；恢复时先读取账本|

默认最大尝试数 3，包含首次，最多重试两次。没有服务端提示时，等待为 0 到 min(cap, base × 2^(attempt_no-1)) 之间的随机值；默认 base=2 秒、cap=30 秒。实际等待时间先提交数据库，再异步等待，不持有事务或数据库连接休眠。

失败处理通过 finish_action 一个事务保存：请求失败分类、ActionAttempt 终态与完成时间、TaskAction 的等待状态/最早时间、关联步骤状态、Run 的等待或长等待暂停，以及相应事件。不能先提交“请求失败”，再另开事务写等待；否则中间崩溃会丢失 Retry-After 约束。长等待暂停在同一事务递增 fencing_token、释放租约；永久失败保持 failed 且没有下次重发时间。

成功和永久失败提交也会写 action_succeeded/action_failed 事件，推进 TaskRun.version 和任务事件游标。状态快照的变化可被 SSE/客户端识别，不需要等步骤最终完成才刷新。

Retry-After 支持秒数和 HTTP 日期；有效提示优先且不被本地 30 秒上限截短。超过允许自动等待时长（默认 300 秒）则暂停，保留最早重试时间；若等待会越过任务截止时间则直接 DEADLINE_EXCEEDED。停止、撤权与截止时间仍受独立监视。

同一任务最多 30 次实际模型请求（含规划和网络重试）、20 个逻辑工具调用；每个动作仍有最大尝试数。只有完整结果进入成功账本，不保存失败片段为成功产物。当前没有任务 token 流，因此不需要把失败半份文本和新文本拼接。

读取超时当前沿用模型配置与外层动作总超时，尚未实现原设计中独立的“10 秒连接、30 秒读取空闲”专用配置；不能据设计文档宣称已具备。

## 6. 调度、恢复与并行

调度器在应用 lifespan 启动，独立于首次问答请求；数据库暂时不可用时记录安全错误并退避扫描。使用 PostgreSQL advisory lock 保持本地单个调度进程，不能以多个 Uvicorn workers 作为扩容方式。

每个 TaskRun 租约固定 30 秒，默认每 5 秒续租；约每秒检查取消、权限和截止时间。领取递增 fencing_token，所有业务提交重验当前 TaskRun/token/租约。旧执行器即使收到迟到网络结果，也不能提交覆盖新执行器的结果。

正常退出取消本进程飞行请求并释放本进程租约；下次启动自动扫描。强制杀进程时，租约到期后才能重新领取。后台恢复会把遗留运行中尝试标为 interrupted，重置未完成步骤；已经成功的 TaskAction 不重做。若动作执行成功但成功结果尚未提交，重启后仍可能重做该只读动作，不承诺外部 exactly-once。

任务默认串行，EA_TASK_PARALLEL_STEPS=2 可让同一批依赖已完成的独立步骤最多两路并行。汇总必须等待所有依赖结果提交；某分支失败时取消本批其他分支，并收敛未结束尝试。同一批中较早完成的分支不会立刻填补下一空闲槽位，属于有界批次并行，不是动态工作窃取。

每个调度进程默认同时执行 2 个 TaskRun，可配置 1–4。步骤并行与任务并发是两层上限，默认最多 2 个任务各执行 1 步。网络等待可能占用一个任务执行槽，但不占用等待事务。每个并发分支使用独立 AsyncSession。

## 7. 权限与身份

沿用 Cookie 登录、受信 Origin、CSRF 和 X-Workspace-ID。Task 的用户与空间从会话和有效成员关系绑定；source_conversation_id 必须为本人当前空间的对话，不会自动复制所有历史消息作为任务上下文。

列表、快照、计划编辑、确认、控制、历史、活动与 SSE 都按本人当前空间过滤。空间管理员不会自动获得别人的任务内容。只读工具继续使用任务所有者身份查询，统计的是 Conversation/Run，**不包含 TaskRun 本身**。

执行和等待时持续检查账号、空间及成员；撤权停止飞行请求和结果发布。SSE 每轮重新检查会话与资源；退出或会话过期会关闭订阅，仍有有效资源权限的后台任务不因单纯浏览器退出自动取消。

事件、公开快照和错误码不包含密码、Cookie、密钥或供应商敏感异常正文。任务目标、输入和步骤结果仍是私有业务资料，数据库访问及备份须保持相同边界。

## 8. REST 契约

所有路径以 /api/tasks 开头。POST 沿用 Origin + X-CSRF-Token；读写均需 Cookie 和当前空间。创建返回 202，其他成功读写返回 200。

|方法/路径|输入和行为|
|---|---|
|POST /api/tasks|goal、idempotency_key、可选 source_conversation_id；显式创建并提交规划|
|GET /api/tasks?offset=0&limit=20|本人任务数组，limit 1–100|
|GET /api/tasks/{id}|权威 TaskSnapshot，不重新执行模型|
|POST /api/tasks/{id}/plan|steps、run_id、revision；追加待确认新版本，最多 3 版|
|POST /api/tasks/{id}/confirm|run_id、revision、digest；绑定精确计划内容|
|POST /api/tasks/{id}/pause、resume、cancel、retry|run_id、version；控制当前执行|
|GET /api/tasks/{id}/runs|本人历次 TaskRun 列表|
|GET /api/tasks/{id}/activity?after_sequence=0|每页最多 100 条持久化事件，按 sequence 继续读取|
|GET /api/tasks/{id}/events?workspace_id={id}&after_sequence=0|快照 SSE；公开空间参数不包含令牌|

TaskSnapshot 包含 task、run、plan、steps、actions、last_event_sequence。公开 actions 仅给出 kind、step_key、status、attempt_count、max_attempts、error_code、next_retry_at 等安全元数据，不返回动作原始输入或模型中间正文。

同键同目标创建复用原任务，同键不同目标/来源返回 IDEMPOTENCY_CONFLICT/409。旧 run、旧 revision/digest、旧 version 返回 409。不存在或非本人资源统一 404，未登录 401，成员或工具权限失效 403，非法计划/额外身份字段 422。

SSE 发送 event:snapshot，data 为完整 TaskSnapshot，id 为单调事件游标；约每 0.5 秒查询状态，约 10 秒心跳。终态发送后结束；会话/权限失效发送 access_revoked。此 SSE 不逐条重放所有语义事件，精确事件重放使用 /activity 分页。重连与读取快照都不会再调用模型或创建任务。

## 10. 已知限制和后续

- 尚未实现 LangGraph 内部节点检查点、步骤内自主 ReAct、自动重规划或子 Agent 委派。
- 手动 retry 重新规划确认，不自动跨 TaskRun 搬运旧统计。
- 页面展示完整步骤结果，尚未做任务 token 流与部分正文续传。
- 只读工具仍仅运行统计；没有企业文档检索、外网搜索、业务写入或审批。
- 本地单调度器，不是分布式 Worker；后端/电脑停止期间不执行。
- lease/fencing 保护本地状态提交，不保证外部系统 exactly-once；未来写入需要幂等键、对账和审批。
- 浏览器视觉、真实模型与完整回归的实际证据分别记录，不用组件或受控 HTTP 代替真实验收。
