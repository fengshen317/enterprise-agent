# 工具调用预算与收尾

更新日期：2026-11-28。

## 当前行为

网页、通讯平台和定时问答复用同一执行入口，按 Run 绑定用户与空间。额度由服务端配置，不要求用户在提问时填写预算。以下为试运行初值，尚未通过真实业务任务集标定为最优值。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| EA_TOOL_SEARCH_MAX_CALLS_PER_RUN | 8 | 已分类搜索工具的单工具配额 |
| EA_TOOL_READ_MAX_CALLS_PER_RUN | 15 | 已分类详情读取、通用只读连接器的单工具配额 |
| EA_TOOL_MAX_CALLS_PER_RUN | 15 | 兼容原配置，业务单工具硬上限，范围 1–100 |
| EA_TOOL_TOTAL_CALLS_PER_RUN | 30 | 当前运行所有业务工具合计获准调用上限，范围 1–200 |
| EA_TOOL_NO_PROGRESS_LIMIT | 3 | 同一查询路径连续返回相同结果或相同错误的阈值 |
| EA_MODEL_MAX_CALLS_PER_RUN | 30 | 主子 Agent 共享的模型动作上限，至少 2 |

单工具实际额度取自身声明、类别额度和业务单工具硬上限的最小值。QQ 邮箱、ima、腾讯新闻、Tavily 的搜索动作使用搜索分类，其余读取动作使用读取分类；个人材料检索和读取分别分类。知识库保留自身 EA_KNOWLEDGE_MAX_CALLS_PER_RUN 配置，默认同步调整为 8。通用 API、CLI、MCP 的已授权只读动作按读取预算执行；写入动作、RSS 聚合和持仓等已有特殊配额仍保留更严格的自身上限，审批规则不变。

旧环境如果显式设置 EA_TOOL_MAX_CALLS_PER_RUN=4，仍会继续压低业务工具额度。希望使用新默认时应将该配置调整为 15 或移除旧覆盖。分类额度可以通过配置调整；不是只在代码中写死 8 和 15。

## 并发计数与审计

迁移 0031 为 tool_calls 增加 is_system 和 budget_reserved。执行器先锁定当前 Run，再在独立事务中检查单工具及业务总量，最后创建审计行和占用额度。主助手、子助手、不同执行器实例都从同一运行的审计计数读取总量，不能各拿一份额度。外部调用期间不持有数据库事务。

已获准的执行尝试即使参数校验失败、超时或报错，也消耗额度；开始前因预算不足而被拒绝的审计记录不占额度。拒绝记录仍有失败终态及错误码。系统计划、委派、技能加载和模型请求不计入业务工具合计，但保留自己的上限；业务总预算用完后不再增加这些工具动作。

历史迁移按已有系统工具名分类，并将历史预算拒绝记录标记为未占用。升级就绪检查要求 schema_version=31；降级只移除新字段，保留原审计记录。

本地更新后，在 backend 目录执行 uv run --frozen --no-sync alembic upgrade head 再启动服务。正式镜像继续通过现有发布入口执行迁移、健康检查和数据验收。

## 无进展检测

主助手与子助手共享本轮执行器内的检测器。同一工具和规范化参数形成一条查询路径。检测器对参数与结果生成带本轮随机密钥的 HMAC 摘要，只把摘要和计数保留在运行内存中，不新增保存关键词、邮件正文、原始响应或错误正文的审计字段。

同一路径连续三次返回相同结果后，第四次不再访问上游，返回 TOOL_NO_PROGRESS；实际调用返回的相同错误也受此限制；参数校验失败消耗调用预算，但不参与基于业务结果的重复检测。结果有变化就重新计数。更换关键词、邮件 ID、分页位置等参数会形成另一条路径，不会被此前的查询阻止。相同路径串行化以防并发绕过，不同路径仍可并行。

检测只应用于无需审批的业务只读工具；写入与系统编排不按返回内容去重。被检测器拦截的尝试照常记录失败，并消耗已经预留的调用次数，防止模型无限重复被拒绝的动作。

该检测不是语义去重：语义相近但参数不同的查询不强行合并。检测状态不跨进程持久化，重建执行器不会恢复内存检测状态；数据库总量计数不受影响。服务重启对未完成运行沿用现有中断恢复策略。

## 收尾与继续查询

每次模型请求前读取预算快照。某个工具耗尽时，只移除该工具，其余工具仍可用；业务总预算达到上限，或共享模型动作即将达到上限时，移除本轮全部工具，要求根据已有真实结果整理回答并说明未覆盖范围。

子 Agent 最多占用模型动作额度的 N−1 次，给主助手保留一次整理结果的机会。被拒绝的子模型预留不会占掉这最后一份额度。模型动作内部的网络重试仍沿用原重试策略，不会重放已完成的工具。图递归上限随模型动作上限设置，避免仍被旧的固定 40 步提前中断。

达到整轮预算边界的主助手回答追加固定提示，说明依据已取得资料整理，用户可以继续说明补查范围。该回答正常保存到对话；用户再发“继续查询某范围”会创建新 Run，获得新的预算，并沿用已保存的成功对话上下文。这不是图检查点续跑，不承诺保留完整工具原始响应，也不会自动重放上一轮写入。

取消、撤权、权限失效和模型故障继续按原失败或取消路径收敛，不为凑收尾而绕过权限。模型长度截断仍保留部分正文并标记失败，不冒充完整成功。

## 验证与评估边界

- test_tool_budget.py：分类额度、参数规范化、结果变化、重复故障、相同路径并发及不同路径并行。
- test_tools_integration.py：真实 PostgreSQL 总预算竞争、不同执行器共享、失败审计、主子模型收尾预留、真实 SDK 图达到预算后整理结果。
- test_tool_budget_migration.py：在独立 PostgreSQL schema 验证历史分类、拒绝计数、升级、降级和审计保留。
- 前端验证重复查询的固定提示；已有流式、失败重试、取消及审批回归继续执行。

自动化模型响应使用受控 HTTP，不代替真实邮箱读取验收。后续应使用真实代表性任务集对照不同预算，比较任务成功率、总调用量、重复与错误比例、耗时和费用，再调整配置；这批初值不代表已完成生产业务评测。
