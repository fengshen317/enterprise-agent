# RSS 订阅与定时简报

2026-11-27。已实现公开 RSS 2.0 / Atom 1.0 连接器，复用现有插件管理、Agent 工具装配、工具审计和定时问答。

## 配置订阅

在「后台管理 → 插件管理」安装「RSS 订阅」，打开配置，勾选需要的预置信源，再点击保存配置。预置目录由服务端统一维护。

| 分类 | 信源 | 内容 |
| --- | --- | --- |
| 官方动态 | OpenAI 官方动态 | 官方公告和文章 |
| 官方动态 | Google AI 官方博客 | Google AI 相关动态 |
| 模型社区 | Hugging Face 社区博客 | 平台与社区的模型、工具文章 |
| 开源发布 | LangGraph 版本发布 | 官方仓库 Release |
| 开源发布 | Deep Agents 版本发布 | 官方仓库 Release |
| 厂商官方项目 | Anthropic · Claude Code | Claude Code 版本与更新说明 |
| 厂商官方项目 | xAI · Python SDK | 官方 Python SDK 发布 |
| 厂商官方项目 | DeepSeek · Harness | 官方 Agent 框架发布 |
| 厂商官方项目 | 豆包相关 · 火山引擎 SDK | 包含方舟接入组件，也覆盖其他云服务更新 |
| 厂商官方项目 | Kimi · Kimi Code | Moonshot AI 官方 Kimi Code 发布 |
| 社交平台 | X / Twitter · 账号动态 | 待配置 RSSHub 账号订阅 |

目录包含 10 个可直接勾选的订阅，以及 X 的待配置入口。厂商官方项目各自覆盖表中产品。Anthropic、xAI、DeepSeek、豆包和 Kimi 的官网全量公告仍需进一步适配，本次验证的可用入口是其官方项目发布源。页面会展示覆盖说明。

X 入口显示为不可勾选，并提示通过自建或可访问的 RSSHub 服务为具体账号生成订阅，再将生成的 HTTPS 地址加入自定义订阅。RSSHub 路由为 `/twitter/user/:id`，回复、转发等附加内容可能需要在 RSSHub 侧设置凭据。适配服务的可用性和账号授权由部署环境验证。[RSSHub 官方路由实现](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/twitter/user.ts)

视频提到的 GitHub 通过项目发布 Atom 接入，Hugging Face 通过社区博客 RSS 接入。视频中的 AIHOT 与 RSS 用于信息聚合和订阅，现有连接器承担订阅读取。

新增安装保持未选择状态。已经保存的订阅地址如果匹配预置信源，会自动显示为勾选，其余地址显示在自定义订阅输入框。加载和查看目录不会自动改写配置，取消勾选后保存才会移除订阅。

需要添加目录以外的源时，在「自定义订阅」中每行填写一个地址。每个地址必须是无需登录、无需凭据的 HTTPS 订阅地址，标准端口为 443。预置与自定义合计支持 1 到 10 个源，重复地址会合并。

后端保持原有 `feeds` 地址数组契约，例如 API 调用可以提交下列内容。

```json
[
  "https://openai.com/news/rss.xml",
  "https://github.com/langchain-ai/langgraph/releases.atom"
]
```

保存后启用插件，点击测试查看健康状态。订阅配置持久化在现有 `connectors.config`，沿用现有管理员配置权限，同一部署的成员共用公开订阅列表。管理员保存配置时校验格式，校验失败保留原配置。

`GET /api/connectors/rss/sources` 向已登录的空间成员返回预置信源的名称、分类、URL 与覆盖说明 `description`。URL 为空且带有说明时表示待配置入口，前端禁用该条目的勾选。目录展示与网络可用性分开检查，运行与手动测试仍使用既有公网地址校验和故障状态。

源需要返回实际 RSS / Atom XML，网站首页和登录页会被标记为格式异常。某些网站没有公开订阅源，需要先提供可访问的 RSS 服务。请勿在源地址中放登录凭据或私人订阅令牌，配置和来源链接对成员可见。

## 问答与定时任务

启用后提供只读工具 `rss__recent`，默认助手可发现该工具。自定义 Agent 需要在能力配置中绑定它。Skill 可保存筛选与总结规则，并绑定已发布版本。源订阅由插件配置保存，Skill 指导如何分析返回资料。

| 参数 | 范围与用途 |
| --- | --- |
| `hours` | 最近 1–168 小时，默认 24，以调用时刻计算 |
| `limit` | 最多返回 1–50 条，默认 20 |
| `query` | 可选关键词，在标题和摘要中做不区分大小写的连续文本匹配 |
| `include_undated` | 默认 false。开启后可以附带无法确认日期的条目 |

返回文章标题、摘要、来源名称、原文链接、源地址、UTC 时间及日期依据。RSS 使用 `pubDate`，Atom 优先 `published`，缺失时使用 `updated` 并注明依据。无时区或无法解析的日期保留为空，未来日期不作为最近新闻返回。

同一文章在一次结果中按原文链接去重，缺链接时按源地址与 GUID 去重。文章按时间倒序排列，未知日期放在末尾。`matched_count` 与 `truncated` 说明是否受到返回条数限制。`undated_count` 说明源中多少条目缺少可确认日期。

先在问答中试运行。

> 使用 RSS 最近文章工具读取过去 24 小时的条目，最多 20 条，筛选与企业 Agent、工具调用、知识库相关的重要进展。最多总结 5 条，每条写明发生了什么、对本项目的影响、发布时间与原文链接。明确说明失败的源、未知日期和截断情况，不把源摘要当成已阅读的全文。

验证结果后，为这条对话建立每日定时任务，时区 `Asia/Shanghai`，例如每天 08:00 使用 `0 8 * * *`。任务指令可以沿用上文，也可指定调用绑定了 RSS 工具和简报 Skill 的私有 Agent。结果存入固定对话，渠道推送沿用任务中的 `push_channels` 配置及对应渠道的绑定和发送条件。

## 运行边界

- 每次工具调用读取当前订阅内容，每源最多处理 200 条。源仅保留近期内容时，更早的历史文章可能无法召回。`feeds[].entry_limit_reached` 提示源解析数量上限。
- 成功解析的源缓存 5 分钟，停用、重启或重新配置时清除。部分源失败返回 `status=partial` 和逐源状态，正常源继续返回。全部失败则调用失败。失败不会被描述为当天没有新消息。
- 以问答、定时任务和现有健康检查触发抓取。当前版本没有独立采集 Worker、历史文章库和跨运行的已投递记录。相邻查询窗口有重叠时可能再次出现同一文章。
- 工具只读取管理员配置的源。运行时校验每跳 HTTPS 重定向的域名解析结果，连接已经校验的公网 IP，并保持原域名的证书校验。内网、回环、测试网段均拒绝。XML 禁用 DTD 和实体，单源响应最多 2 MiB，摘要转纯文本并截到 1500 字符。
- 本机 TUN 代理启用 Fake-IP 时，域名可能解析到 `198.18.0.0/15` 等测试网段。应为订阅域名设置真实 DNS 解析及可用出站路由，再在插件页测试。连接器不使用环境变量代理。
- 模型总结需要部署中的真实模型配置。解析和受控模型测试只验证协议与调用链路，实际信息质量需用目标订阅源和真实模型验收。

## 后续规划

历史归档、订阅分类、个人订阅与跨次投递去重需要另行增加数据模型和投递状态。当前实现保持可重试的时间窗口查询，读取不会把文章标为已发送。
