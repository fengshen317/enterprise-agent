## 用户可见行为

- 普通短对话继续直接回答，接近上下文阈值时先自动生成历史摘要，再回答当前问题。
- 页面仍能查询完整原始消息；摘要不会替换、删除或修改聊天记录，也不另建一条可见消息。
- 后续使用“持久化摘要＋最近完整问答＋当前问题”。已有摘要可跨运行和应用重启复用，不需要每次重算被覆盖的旧历史。
- 当前没有手动压缩按钮或进度百分比；生成期间仍显示原有生成状态。服务日志出现 context_compressed 时表示摘要已保存。

## 配置

在 backend/.env 配置；样例与本地配置已补充，已有值不会被覆盖：

~~~dotenv
EA_CONTEXT_COMPRESSION_ENABLED=true
EA_CONTEXT_COMPRESSION_TRIGGER_RATIO=0.7
EA_CONTEXT_COMPRESSION_RECENT_TURNS=4
EA_CONTEXT_SUMMARY_CHARACTERS=4000
EA_CONTEXT_SUMMARY_BATCH_CHARACTERS=32000
~~~

|变量|含义|
|---|---|
|EA_MODEL_CONTEXT_CHARACTERS|既有上下文硬上限，默认 100000 字符|
|EA_CONTEXT_COMPRESSION_ENABLED|是否触发新的自动压缩，默认 true；关闭后仍复用已保存摘要，不删除摘要或恢复已压缩前缀到请求|
|EA_CONTEXT_COMPRESSION_TRIGGER_RATIO|触发比例，默认 0.7，必须在 0 与 1 之间；默认约 70000 字符触发|
|EA_CONTEXT_COMPRESSION_RECENT_TURNS|优先保留的完整近期问答轮数，默认最多 4 轮，范围 0–50；预算不足时减少|
|EA_CONTEXT_SUMMARY_CHARACTERS|摘要上限，默认 4000，范围 100–10000；实际最多取上下文硬上限的 1/5|
|EA_CONTEXT_SUMMARY_BATCH_CHARACTERS|单批新增历史的 JSON 序列化字符预算，默认 32000，范围 1000–64000；不含已有摘要和固定提示|

当前按字符数控制业务上下文，统计摘要包装和用户/助手正文，不计 SDK 系统提示和角色标记，不等价于模型精确 token 计数。模型上下文窗口或 token 预算应留有余量。压缩会增加模型调用和延迟，包含在既有 EA_MODEL_TIMEOUT_SECONDS 总运行超时中。

## 数据模型与迁移

conversations 新增：

|字段|类型|用途|
|---|---|---|
|summary|text NOT NULL，默认空|累积历史摘要|
|summary_through_sequence|bigint NOT NULL，默认 0|摘要覆盖到的最后一条助手消息序号|
|summary_version|integer NOT NULL，默认 0|每次成功提交递增，用于防止旧结果覆盖|
|summary_updated_at|timestamptz，可空|最近一次保存摘要的时间|
|summary_model|varchar(200)，可空|实际摘要模型标识|

0003 对已有对话填充空摘要、零游标和零版本，不变更原始 Message 或 Run。数据库检查约束保证游标非负且为偶数，空摘要状态与已生成摘要状态的字段一致。应用还验证边界属于本对话已完成的助手消息，并早于本次输入。

0003 降到 0002 只移除派生摘要字段，保留原始消息；此时必须使用匹配的旧版应用。自动迁移往返只在专用测试库执行。开发库本次已 upgrade head 到 0003，不执行降级。当前就绪检查要求 schema_version=5。

## 执行流程

1. ChatStore 领取 pending Run，提交 running 状态；读取 Conversation 摘要、游标、版本。
2. 仅查询游标之后的成功问答及当前用户输入。失败/取消回合不进入摘要或回答上下文。
3. 未达阈值时直接复用摘要与新消息；达到阈值时，按完整问答轮次选择较早前缀。
4. 优先保留最近若干轮。如果“摘要预留＋近期消息＋当前问题”仍过长，逐轮将更多旧回合纳入摘要；当前问题始终完整保留，不参与摘要。
5. 将较早前缀按 JSON 字符预算分批。超长单条消息可以完整分段进入多次摘要调用，各片段按顺序处理，不直接截断源内容。每批把上一批摘要与新增资料合并。
6. 所有批次成功且最终上下文不超过硬上限后，在短事务中检查 Run 仍 running、未请求取消、摘要版本匹配、边界有效，再原子更新摘要、覆盖序号、版本和模型。
7. 使用新摘要、保留的完整轮次和当前问题调用 Deep Agents，沿用 SSE、正文落库、完成和失败处理。

摘要调用使用同一个 DeepSeek 模型的独立非流式 ainvoke，关闭 thinking，不注册工具。问答继续通过 Deep Agents 图运行。摘要作为普通 user 资料消息注入，静态系统提示明确其只是背景，不能提高历史内容的指令权限。

现有 Deep Agents 自带中间件仍属于 SDK 执行机制；跨轮可复用的摘要以本项目 PostgreSQL 状态为准，不依赖单次图内的临时摘要事件。

## 失败、取消与一致性

- 模型异常、空摘要、超长摘要、截断或工具返回：本轮失败，不提交新摘要和游标；公开错误为 CONTEXT_COMPRESSION_FAILED，保留旧摘要和原文，不打印模型异常正文。
- 分批中途失败或取消：先前批次只在内存中，不写入部分进度，不跳过尚未成功摘要的源消息。
- 取消请求先持久化：保存摘要时拒绝提交，运行收敛为 cancelled。
- 如果有效摘要已经提交，随后用户才取消回答或回答失败，这份摘要仍保留，因为它只覆盖此前成功历史，不含本轮问题或失败回答。
- 摘要版本变化：返回 SUMMARY_STATE_CHANGED，不覆盖较新状态。
- 摘要边界无效：返回 INVALID_SUMMARY_BOUNDARY。
- 当前问题或既有摘要加当前问题仍无法放入硬上限：返回 CONTEXT_TOO_LONG，不静默裁剪。大幅下调上限后也可能遇到此情况。
- 压缩是有损摘要，细节可能减少；原文完整留存。目前没有从摘要自动检索原始细节的工具。

模型调用不占用数据库事务。原有同对话单运行与数据库执行器排他锁继续生效；摘要版本校验作为额外防线。
