# 腾讯会议结束后自动生成会议总结 — 设计方案

> **状态**：规划中（未实施）
> **日期**：2026-11-12
> **需求来源**：腾讯会议结束后自动触发会议总结任务，由项目内 Agent 完成总结，结果在前端展示

## 一、需求

1. **触发**：腾讯会议 Webhook 通知会议结束 → 调用项目 API
2. **数据获取**：通过 wemeet CLI（命令行工具）获取会议转写文本
3. **总结生成**：项目内的 Agent（ChatRuntime + DeepSeek）生成会议总结
4. **结果展示**：总结结果显示在前端（微信推送暂不做）

## 二、总体架构

完全复用现有"DB 落账 + 轮询唤醒 + ChatRuntime 执行"模式（与 `ScheduleRuntime` 同构），不引入新的事件机制：

```
腾讯会议开放平台回调
   │  POST /api/webhooks/wemeet（签名校验，无 Cookie/CSRF）
   ▼
meeting_summaries 落一行 status='received'（幂等）→ poke()
   ▼
MeetingSummaryRuntime（asyncio 轮询 + asyncio.Event 唤醒，advisory lock 782341919）
   ├─ ① received/fetch_retry ──► WemeetCliClient.fetch_transcript()
   │        成功 → status='generating'；失败且 attempts<上限 → status='fetch_retry'（退避）
   ├─ ② generating ──► chat_runtime.store.create_conversation() 建专属对话
   │        chat_runtime.create_run() + schedule()（完全复用 ChatRuntime 生成链路）
   └─ ③ generating 且 Run 终态 ──► completed / failed
   ▼
前端 /meetings 列表与详情（总结正文 = Run 的 assistant 消息，不冗余存储）
```

**核心决策**：总结生成不新建执行器。`ScheduleRuntime._execute()` 已证明 `chat_runtime.create_run(conversation_id, RunCreate(...), scope)` + `schedule()` 就是"服务端触发 Agent 运行"的标准姿势，会议总结只是又一种触发源（幂等键 `meeting_{summary_id}`）。

## 四、Webhook 接收端点

新建 `backend/app/api/webhooks.py`（`APIRouter(prefix="/api/webhooks", tags=["会议集成"])`）：
- **不使用** `ScopeDependency`/`IdentityDependency`（非浏览器流量，天然无 Cookie 与 CSRF）
- **签名校验**：请求头 `X-Wemeet-Timestamp`、`X-Wemeet-Signature`，签名 = `HMAC-SHA256(EA_MEETING_WEBHOOK_SECRET, f"{timestamp}:{raw_body}")`，用 `hmac.compare_digest` 常量时间比较
- **防重放**：时间戳与当前时间差超过 `EA_MEETING_WEBHOOK_REPLAY_WINDOW_SECONDS`（默认 300s）拒绝
- **幂等**：`event_key` 唯一约束（无 `event_id` 时用 `meeting_id + ended_at` 合成）；重复投递返回既有记录 202
- **只落库 + poke**，立即返回 202，不做任何耗时操作
- `EA_MEETING_WEBHOOK_SECRET` 未配置时返回 503（`MEETING_WEBHOOK_DISABLED`）

签名校验函数放 `backend/app/core/security.py`（纯函数，便于单测）。

## 五、wemeet CLI 集成

新建 `backend/app/services/wemeet.py`（仿 `services/ragflow.py` 的 Protocol + Client 模式）：

```python
class WemeetClientProtocol(Protocol):
    async def fetch_transcript(self, meeting_id: str) -> TranscriptResult: ...
    async def aclose(self) -> None: ...

class WemeetCliClient:
    """通过 asyncio.create_subprocess_exec 调用 wemeet CLI 获取转写。"""
```

- 调用形态：`wemeet transcript --meeting-id <id> --format text`
- `TranscriptResult` 分类：`ok(text)` / `not_ready`（转写未就绪，退避重试）/ `failed(code)`（不可重试）
- `create_subprocess_exec`（不经 shell，防注入）+ `asyncio.wait_for` 超时后 kill 进程
- CLI 路径可配（`EA_WEMEET_CLI_PATH`），超时可配

## 六、MeetingSummaryRuntime（核心链路）

新建 `backend/app/services/meeting_runtime.py` + `meeting_store.py`（仿 `schedule_runtime.py`/`schedule_store.py`）：

- **状态机**：`received → fetching → generating → completed | failed`
- **原子领取**：`with_for_update(skip_locked=True)`
- **转写拉取**：not_ready → `fetch_retry` + 指数退避；超限 → `failed`
- **触发 Agent**：
  1. 创建专属对话：`chat_runtime.store.create_conversation(f"会议总结：{subject}", scope)`
  2. 组装提示词：常量 `MEETING_SUMMARY_PROMPT` 放 `app/capabilities/prompts.py`（结构化输出：议程回顾、关键结论、行动项【负责人/时限】、风险与分歧）
  3. 转写超 `EA_MEETING_TRANSCRIPT_MAX_CHARACTERS`（18000）时头尾保留式截断
  4. `RunCreate(content=提示词, idempotency_key=f"meeting_{id}")` → `create_run()` → `schedule()`
- **收尾**：轮询 Run 终态，总结正文不复制，从 assistant 消息读取
- **锁**：advisory lock `782341919`（避开 782341912/15/17）

## 十、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 转写未就绪 | 会议结束 ≠ 转写可拉取 | not_ready 分类 + 退避重试 + 手动 retry 兜底 |
| RunCreate.content 20000 上限 | 长会议转写截断 | 截断到 18000（头尾保留），配置可调 |
| Webhook 是唯一未鉴权面 | 恶意请求 | 强制签名 + 防重放 + 严格校验 + 503 默认关闭 |
| 归属配置错误 | 事件被静默丢弃 | 落 failed + error_code=MEETING_OWNER_INVALID |
| 重复事件/周期性会议 | 重复生成 | event_key 唯一 + 幂等键兜底 |
