# 对话内规划与子 Agent

## 已确认方向

用户于 2026-11-05 确认：问答作为统一入口，复杂目标按需规划、委派子 Agent，并在消息内展示执行情况；只读能力自动执行。移除独立的计划执行导航，不再要求用户提交 JSON 或确认每个只读计划。

## 实施步骤

1. 在现有 Deep Agents 对话图注册受控计划和批量委派工具；子 Agent 使用独立图与上下文，继承运行归属，不允许递归委派。
2. 复用 tool_calls 保存计划、子任务状态和结果；不新增数据库实例或迁移，不删除历史 tasks 数据和后端兼容接口。
3. 复用网络异常分类和退避；仅重试单次模型调用，不重放已完成工具。失败尝试正文不进入对话；取消传播到子任务。
4. 问答消息内自动展示计划与执行记录，提供停止和失败后重试；移除独立页面路由，旧地址回到问答。
5. 验证真实 SDK、数据库权限、并行与取消、网络失败及前端展示，更新验收结果。

## 边界

子 Agent 首轮角色为分析员与复核员，最多两个并行、单层委派；只有本人当前空间运行统计工具。无联网检索、文件执行或业务写入。历史独立任务的动作恢复能力保留在旧后端，但不能据此宣称对话图支持重启续跑；对话重启仍标记中断，用户可在原对话重试。

## 已实现架构

浏览器 ChatView → 原问答 Run API → ChatRuntime → DeepSeekProvider 主图 → ChatAgentExecutor → 计划记录/只读工具/独立子图 → 主图汇总 → 原 Message 正文。

- 简单问题由模型直接回复；复杂目标由模型按需调用规划和委派工具，不使用关键词硬分类。
- update_plan 接受最多 8 个步骤，字段为 title 和 pending/in_progress/completed 状态。每轮最多更新 12 次；每次提交完整公开计划，页面展示最后一次成功更新。
- delegate_tasks 接受每批 1–2 个相互独立子任务，字段为 role（analyst/reviewer）、title、instruction。单轮最多执行 6 个子任务，各批次共享最多两个执行槽。
- 每个子任务使用独立 Deep Agents 图与独立消息上下文；只得到主 Agent 明确提供的 instruction，不自动拷贝全部对话，也不共享可变图状态。子图只暴露 get_my_run_stats，不能递归委派、更新主计划或使用 SDK 文件等内置能力。
- 主图与子图共享本轮统计查询配额 EA_TOOL_MAX_CALLS_PER_RUN（默认 4）；计划和委派分别计数，不消耗统计查询配额。数据库 Run 行锁保护并行计数，每个实际查询独立会话。
- 每轮最多保留 30 个逻辑模型动作，每动作最多 EA_TASK_RETRY_ATTEMPTS 次实际请求（默认 3，最多 5），图循环上限 40。所有主/子 Agent 共享该运行限制。
- 新一轮引用同一对话最近一轮的最新成功计划与最近两个成功子任务，连同原目标作为普通背景资料注入。每条资料最多 6000 字符、超出有截取标记；失败或中断子任务正文不注入。原始记录仍完整保存。每次模型请求检查完整上下文上限。

## 数据与接口

不新增迁移，head 仍为 0008；现有 tasks/TaskRun 不作为问答规划的必填对象。旧 /api/tasks 后端保留兼容，旧 /tasks 前端地址重定向 /chat，原 TasksView 源码没有挂载到正式路由。

复用 GET /api/runs/{run_id}/tool-calls，沿用当前用户、工作空间、私有对话与 Run 资源鉴权。新增 tool_name：

|标识|result 内容|状态说明|
|---|---|---|
|update_plan|steps 完整计划|completed 表示计划保存成功，步骤状态是主 Agent 报告，不能替代实际执行证据|
|delegate_tasks|results，各项含 ok 和子任务审计标识|任一子任务失败时批次为 failed，返回 ok=false；已成功分支结果保留|
|delegate_agent|role、title，成功后有 output|running/completed/failed/cancelled 对应真实独立图运行|
|model_request|attempt、max_attempts；等待时另含 error_code、next_retry_at|单个模型动作，可在同一动作内有限重试；不保存原始异常正文|

子任务指令作为模型输入使用，不持久化在审计公开字段；结果仅当前对话所有者可查，管理员没有读取他人对话的例外。进度提交和结果发布前重验权限，主运行每秒复核权限，取消通过 TaskGroup 等待子分支退出。

问答 POST/GET/SSE 契约保持兼容，不增加预算或手工计划 JSON 字段。前端在消息内默认展开当前执行状态，可折叠历史记录。SSE 保持完整快照替换，执行记录通过现有审计接口轮询；失败后重试或停止后补充要求都在原对话创建新 Run，旧记录保留。

## 网络、超时与取消

- 复用 task_retry 的网络异常分类：408/429/500/502/503/504 与瞬时网络错误可重试；认证、账户余额、证书、永久地址错误和未知错误不盲重试。
- max_retries=0；只重试当前模型 handler，不重启已执行的工具或子任务。已失败的实际请求正文不发送到 Message，也不与重试正文拼接。
- Retry-After 秒数/日期优先，不截短服务端有效等待。超过 EA_TASK_RETRY_MAX_WAIT_SECONDS（默认 300）明确失败，页面提供稍后手工重试；不是旧 Task 的长期暂停机制。
- EA_MODEL_TIMEOUT_SECONDS（默认 120）是单请求 SDK 超时；EA_CHAT_RUN_TIMEOUT_SECONDS（默认 1800，最大 3600）是整轮含子任务、等待和上下文处理的总时限。网络等待不持有事务。
- SDK 接收流式网络响应，但正文按完整成功模型动作发布，未承诺逐 token 展示。进度记录在执行期间持续更新。
- 停止本轮会取消主图和所有正在运行子任务，并保留已完成子任务记录；新一轮可参考这些成功资料。手工重试创建新 Run，可能重新查询实时数据，不承诺跨 Run 工具去重。
- 断开浏览器不取消任务；退出登录关闭订阅但合法执行继续。撤销成员、禁用账号、归档空间会停止运行。服务重启使旧问答运行失败，当前不是 LangGraph checkpointer 恢复实现。
