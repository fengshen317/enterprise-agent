## 三类记录的职责

- Conversation 是对话容器，承载标题、归档状态及消息序号分配。
- Message 是内容记录，一条用户消息或一条助手回复。流式片段更新同一条助手消息。
- Run 是一次生成尝试，保存模型、状态、幂等键、错误与执行时间。它不是业务任务。

所有业务主键为应用生成的 UUID，所有时间为 PostgreSQL timestamptz。当前没有用户与工作空间字段，阶段三补充归属与迁移策略。

## conversations

|字段|类型|说明|
|---|---|---|
|id|UUID PK|对话标识|
|title|varchar(200)|必填；标题内容校验由后续接口实现|
|status|varchar(20)|active / archived，默认 active|
|next_message_sequence|bigint|下一可用序号，默认 1，必须为正|
|created_at / updated_at|timestamptz|默认数据库 now()，业务更新显式维护 updated_at|

索引：(updated_at, id)，为稳定分页预留。无自动更新触发器。

## runs

|字段|类型|说明|
|---|---|---|
|id|UUID PK|单次生成标识|
|conversation_id|UUID FK|所属对话|
|idempotency_key|varchar(100)|同一对话内唯一且非空|
|status|varchar(20)|pending / running / completed / failed / cancelled|
|model|varchar(200)|本次使用的模型标识|
|input_sequence|bigint|本次用户输入序号，必须为正|
|error_code / error_message|varchar(64/500)，可空|仅保存经过脱敏的公开错误|
|cancel_requested_at|timestamptz，可空|请求取消时间|
|started_at / finished_at|timestamptz，可空|执行起止时间|
|created_at|timestamptz|创建时间|

约束：

- unique(conversation_id, idempotency_key) 保留幂等历史，失败也不能复用旧键创建新尝试。
- 部分唯一索引 uq_runs_one_active_per_conversation：只对 pending/running 生效，同一对话只能有一个未结束运行。
- pending/running 要求 finished_at 为空；终态要求 finished_at 非空。
- unique(conversation_id, id) 用于助手消息的复合外键。
- input_sequence 尚未使用外键，避免运行与用户消息互相依赖的插入环；问答服务负责在同一事务内创建、验证输入消息。数据库目前只保证它为正数。

## messages

|字段|类型|说明|
|---|---|---|
|id|UUID PK|消息标识|
|conversation_id|UUID FK|所属对话|
|run_id|UUID，可空|助手消息对应的生成尝试；用户消息为空|
|sequence|bigint|对话内严格有序，必须为正|
|role|varchar(20)|user / assistant|
|content|text|默认空字符串，支持逐批累积|
|status|varchar(20)|streaming / completed / interrupted|
|created_at / updated_at|timestamptz|默认 now()，ChatStore 显式更新 updated_at|

约束：

- unique(conversation_id, sequence) 保证同一对话消息排序不冲突。
- unique(run_id) 保证一次运行最多产生一条助手消息；PostgreSQL 允许多条用户消息使用 NULL。
- 复合外键 (conversation_id, run_id) → runs(conversation_id, id)，禁止绑定其他对话的运行。
- user 必须 run_id 为空、status=completed；assistant 必须绑定运行。
- 外键使用默认限制删除行为，不启用级联删除。本阶段不提供物理删除接口。

## 事务与状态规则

数据库检查约束保障合法取值、唯一性和关联，不保障跨表状态同步或合法状态跳转。ChatStore 负责锁行、分配序号、原子写入、终态幂等和 updated_at 更新，相关接口及执行器测试已覆盖并发与取消。

计划流转：pending → running → completed/failed/cancelled；pending 也可直接失败或取消。运行失败或取消时助手消息改为 interrupted，完成时改为 completed。重试生成新 Run，旧错误与部分内容保留。

## 初始化与回退

在 backend 目录执行：

~~~bash
uv run alembic upgrade head
uv run alembic current
uv run alembic check
~~~

0002 增加三张业务表；0003 在 conversations 增加摘要、覆盖序号、版本、更新时间和模型，标记升级为 3。当前健康检查要求版本 3；旧库返回 SCHEMA_NOT_READY，需先迁移。

0002 降级到 0001 会删除三张业务表及其数据，并将标记恢复为 1；仅在可丢弃测试库自动验证，开发库不执行降级。当前所有业务表仍位于同一开发数据库，无额外数据库实例。
