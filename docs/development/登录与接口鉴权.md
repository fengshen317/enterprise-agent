# 登录与接口鉴权

日期：2026-11-03。迁移版本：0005。本地登录、私有资源隔离及前端已实现；管理员账号由本机操作者显式初始化。

## 首次使用

在 backend 目录执行：

~~~bash
uv sync --frozen
uv run alembic upgrade head
uv run python -m app.cli.accounts init --username admin --claim-legacy
~~~

按终端提示输入并确认密码，输入时明文显示。不限制密码长度或字符组成（包括空字符串），不裁剪输入；仍需两次输入一致。密码不通过参数或 .env 传递，数据库继续保存 Argon2id 哈希。该命令创建默认空间及 admin 成员；--claim-legacy 明确将所有原本无归属的本地对话认领给该账号。原有消息、Run、摘要、游标与版本不变，不覆盖已经拥有归属的数据。

已有账号不要重复初始化；重复运行会拒绝并保留原密码。若不想立即认领，去掉 --claim-legacy，之后再单独认领。若发现未结束旧运行，认领会拒绝并回滚本次初始化：可先不带认领标志创建账号，重启后端并登录工作台触发旧运行收敛，再执行 claim-legacy。

停止旧后端，再启动：

~~~bash
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
~~~

另一个终端在 frontend 执行 npm ci、npm run dev，打开 http://127.0.0.1:8686/login。推荐同源 /api 代理；不要混用 localhost 与 127.0.0.1 做跨站 Cookie 直连。

## 本机账号命令

~~~bash
# 为已有空间添加普通成员
uv run python -m app.cli.accounts add-user --username alice --display-name 成员甲 --workspace default

# 重置密码，立即使此前全部会话版本失效
uv run python -m app.cli.accounts reset-password --username admin

# 之后显式认领剩余无归属历史，重复执行不会覆盖已归属记录
uv run python -m app.cli.accounts claim-legacy --username admin --workspace default
~~~

init / add-user / reset-password 交互输入密码。claim-legacy 不需要再次输入应用密码，但命令依赖本机数据库权限，目标必须是活跃空间中的有效管理员。它是受信本机管理入口，不向网络暴露账号创建或认领接口。当前没有自助注册、找回密码或 SSO；已增加受管理员保护的成员管理页面，见 [后台用户与角色管理](后台用户与角色管理.md)。

## 会话与密码

- 使用 pwdlib 0.3.1 的 Argon2id 哈希，不自写密码算法；哈希和验证在线程中执行，避免阻塞事件循环。
- 登录成功生成 32 字节随机不透明令牌，原始令牌只通过 ea_session Cookie 传递，数据库仅保存 SHA-256 摘要。
- Cookie 为 HttpOnly、SameSite=Lax、Path=/api；本机 HTTP 默认 Secure=false，production 环境强制 Secure=true。默认会话绝对过期时间 12 小时，没有滑动续期或 refresh token。
- 每次认证检查数据库里的过期、撤销、账号 active 和 session_version。重置密码递增账号版本，旧会话立即失效。
- 同一浏览器再次登录轮换旧 Cookie 并撤销旧会话。退出幂等撤销当前会话并删除 Cookie，不自动撤销其他设备的独立会话。
- 未知账号、错误密码和禁用账号统一返回 INVALID_CREDENTIALS，不回显密码或哈希。未知账号也执行虚拟哈希验证，减少明显时间差。

参考：[pwdlib 官方使用说明](https://github.com/frankie567/pwdlib/blob/main/docs/guide.md)。

## CSRF 与登录失败限制

所有状态修改请求必须带受信 Origin。登录通过来源检查防止跨站登录；已登录业务写入额外要求 X-CSRF-Token，值由原始会话令牌派生，绑定当前会话并用常量时间比较。GET /api/auth/me 向同源页面返回校验值，原始 Cookie 仍不可被脚本读取。不能用 SameSite 或隐藏按钮替代这些校验。

失败窗口按“规范化账号＋框架提供的客户端地址”摘要存入 PostgreSQL，默认 15 分钟内最多 5 次失败；达到上限返回 429。并发更新锁定同一窗口行，后端重启不会清空限制。反向代理地址信任须随部署配置审查；本地窗口不是完整的公网防爆破与全局流量限制。过期会话和登录窗口清理任务后续在工程加固阶段补充。

## 接口

|接口|鉴权和用途|
|---|---|
|POST /api/auth/login|Origin＋username/password；成功设置 Cookie，返回用户、成员空间、过期时间和 csrf_token|
|GET /api/auth/me|Cookie；恢复会话与空间列表，响应 no-store|
|POST /api/auth/logout|Origin；携带 Cookie 时要求匹配 CSRF；204 清除 Cookie，重复退出安全|
|GET /api/workspaces|Cookie；仅返回当前用户 active 成员关系对应的空间|
|现有全部 /api/conversations 与 /api/runs 路由|Cookie＋空间选择；写入额外要求 Origin 和 CSRF|
|GET /api/health/live、/ready|保持匿名可用，仅用于进程和数据库健康，不返回业务内容|

旧问答路由仍沿用原路径，但已统一要求鉴权，不保留匿名兼容入口。OpenAPI 为业务路由标记 Cookie 安全方案，并展示 X-CSRF-Token 与 X-Workspace-ID 参数。/docs 和 OpenAPI 本身仍是本机公开开发元数据。

REST 使用 X-Workspace-ID 选择空间；用户 ID 从会话中取得，不接受正文 user_id、created_by_user_id 等字段绑定可信身份。EventSource 无法自定义该请求头，所以 SSE 可使用 /api/runs/{run_id}/events?workspace_id={id}；URL 只包含公开资源标识，绝不放会话令牌。

接口调用顺序：登录并保存 Cookie → 从登录响应取得 csrf_token 和空间 id → 后续请求带 Cookie、X-Workspace-ID；POST 再带 X-CSRF-Token 和受信 Origin。生产调用者也必须遵循此协议，不能省略写操作校验。

公开错误码：AUTH_REQUIRED（401）、INVALID_CREDENTIALS（401）、LOGIN_RATE_LIMITED（429）、ORIGIN_DENIED / CSRF_INVALID / WORKSPACE_ACCESS_DENIED（403）、WORKSPACE_REQUIRED（400）、WORKSPACE_ARCHIVED（409）。非本人资源统一返回 CONVERSATION_NOT_FOUND / RUN_NOT_FOUND（404）。参数错误沿用 422。

## 私有资源规则

当前用户必须为 active 账号且持有目标空间 active 成员关系。对话还必须同时属于该用户与所选空间。空间管理员和普通成员读取私有对话的边界相同，管理员不会自动获得他人聊天内容。

列表直接按 workspace_id 与 created_by_user_id 过滤；历史、创建运行、运行查询、取消和 SSE 查询同样校验。新建时后台绑定归属，客户端提交冒充身份字段不起作用。创建和发送的事务内再次复核空间与成员状态。

Message、Run 和持久化摘要都通过 Conversation 继承同一归属，不单独接受另一套用户或空间字段。空间归档后允许读取自己的历史和停止自己的运行，禁止新建和发送。

SSE 建立前检查权限，每个 250ms 轮询继续复核会话和资源。退出、过期、禁用或撤销成员后发送 access_revoked 安全事件并关闭连接，不再发送正文；前端关闭订阅并清理当前登录态。退出会话不会自动取消仍有资源权限的后台问答，符合原有浏览器断开不取消生成的规则。

执行器约每秒独立检查账号、空间、成员与对话状态；即使模型没有新片段，撤权也会停止进行中的生成，保存已收到内容，Run=failed / ACCESS_REVOKED，助手消息=interrupted。检查是周期性的，不能撤回已经发送给供应商的请求或已经交付的内容。

## 数据模型与迁移

0005 新增：

|表/字段|说明|
|---|---|
|auth_sessions.id|UUID 主键|
|auth_sessions.user_id|关联 users|
|auth_sessions.token_digest|唯一 SHA-256 摘要，原始令牌不入库|
|auth_sessions.session_version|创建时的用户会话版本|
|auth_sessions.created_at / expires_at / revoked_at|创建、过期、撤销时间；过期时间必须晚于创建时间|
|auth_login_limits.key_digest|账号与连接地址摘要主键|
|auth_login_limits.failures / window_started_at|失败次数与窗口起点|
|conversations.workspace_id / created_by_user_id|成对为空或成对非空；复合外键关联 workspace_memberships|

已有无归属对话不自动猜测所有者，暂留两个 NULL 值并从受保护接口隐藏。认领命令只填归属字段，不改内容和摘要；新建接口只能生成有归属记录。为了允许安全隔离尚未认领的历史，当前没有强制所有旧记录立即变为 NOT NULL，替代方案是成对约束、成员复合外键与严格查询过滤。

0005 降级移除会话和归属元数据，会丢失会话与归属分配，不应作为开发数据的默认回滚方式。自动迁移往返只在专用可丢弃测试库执行。当前开发库与测试库 head=0007，健康标记为 7；0006 增加工具审计，不改变登录和对话归属规则，见 [原生工具与调用审计](原生工具与调用审计.md)。

## 前端与配置

Pinia 管理会话和空间选择；原始会话令牌由浏览器 Cookie 管理。CSRF 值只在内存，localStorage 仅记忆公开空间 ID 和跨标签页状态变更信号，不存密码或会话令牌。登录后清空密码字段，失败也清空。切换空间按用户＋空间重新挂载问答页，关闭旧订阅；迟到的会话恢复响应不能在退出后恢复旧用户。

|变量|默认与说明|
|---|---|
|EA_AUTH_SESSION_HOURS|12，范围 1–168|
|EA_AUTH_COOKIE_SECURE|false，本机 HTTP 使用；production 强制 true|
|EA_AUTH_LOGIN_MAX_FAILURES|5，范围 1–20|
|EA_AUTH_LOGIN_WINDOW_SECONDS|900，范围 60–3600|
|EA_AUTH_TRUSTED_ORIGINS|默认 localhost/127.0.0.1 的 8686 和 8000，精确 Origin，无路径或尾斜杠|

自定义端口时同时更新可信来源和需要的 CORS 来源。没有 JWT_SECRET 配置，因为本项目采用可撤销的服务端会话。
