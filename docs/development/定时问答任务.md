# 定时问答任务

日期：2026-11-11，2026-11-19 更新。状态：已实现（本地单进程范围）。迁移 `0009`、`0019`、`0022`。

## 能力与边界

- 按五段 Cron 向一个**固定对话**追加新的问答 Run；结果继续走现有 SSE、历史记录、停止与重试链路。
- 创建任务时可以直接新建一个对话并固定使用，也可以选择已有对话。
- 复用现有规划、只读工具和单层子 Agent，不新增第二套 Agent 执行链路。
- 支持创建、列表、完整编辑、启停、删除和“运行一次”。
- 可选中国法定工作日或沪深 A 股交易日筛选，适用于自动触发。旧任务默认不筛选日期。
- 主 Agent 可查找并原地修改本人当前空间的任务。审批卡展示前后值，仅已批准且配置版本仍一致时写入。
- 每条任务独立配置“推送结果到微信”，默认关闭；已有任务迁移后也保持关闭。“运行一次”和 Cron 触发使用同一开关。
- 创建后每次触发都向同一对话追加消息，并沿用其 Agent 配置和上下文压缩策略。
- 同一对话已有活跃运行时，本次触发记录为 `skipped`，不会排队或补跑。
- 错过的多次触发只保留最近一次，不补跑积压；服务重启后已提交运行按现有问答规则收敛。
- 不支持独立 Worker、跨进程调度、微信以外的通知渠道和任意图节点续跑。

## 架构

```text
Vue SchedulesView
  → /api/schedules（CRUD / run）
  → ScheduleRuntime（单进程轮询 + PostgreSQL advisory lock 782341917）
  → ScheduleStore.claim_due（SKIP LOCKED，先推进 next_run_at）
  → ChatRuntime.store.create_run（固定对话、幂等键）
  → ChatRuntime.schedule（现有真实问答生成）
```

- `ScheduledTask` 只保存定义、固定对话和最近一次触发结果；消息与运行仍保存在原有 `messages`、`runs` 表。
- 调度器与问答执行器分别持锁，但调度器在领取前调用 `ChatRuntime.ensure_ready()`；重复后端进程不会执行定时任务。
- `claim_due` 在同一个事务内使用 `SELECT ... FOR UPDATE SKIP LOCKED`，先写入下一次触发时间；进程在创建运行前崩溃时最多丢失一次触发，不会重复执行。
- 幂等键格式为 `schedule_{id}_{触发时间}`；同一触发重复创建运行会返回已有快照。
- 触发时重新校验账号、空间成员、对话归属和对话状态；撤权或归档只记录跳过，不创建运行。

## 数据模型

|字段|说明|
|---|---|
|`workspace_id`、`owner_user_id`|可信归属；外部请求不能指定|
|`conversation_id`|固定结果对话；删除对话时级联删除任务|
|`name`、`prompt`|公开名称与到期提交的问题|
|`cron_expression`、`timezone`|五段 Cron 与 IANA 时区|
|`calendar_mode`|`all_days`、`cn_workday` 或 `cn_a_share`|
|`enabled`、`next_run_at`|启用状态与下一次 UTC 触发时间；停用或等待日历时为 NULL|
|`calendar_waiting_year`|待补充的公告年份；日历补齐并部署后自动从当前时间重算|
|`revision`|配置版本；调度器推进触发时间和回写运行结果时保持此版本|
|`push_to_wechat`|是否把本任务结果主动推送到已绑定微信；默认 false。与 `push_channels` 里有没有 `ilink` 保持一致|
|`push_channels`|要推送的渠道列表，取值为 `ilink`、`feishu`、`dingtalk`、`qq`。空列表表示不推送，不是投递失败|
|`last_run_at`、`last_run_id`|最近一次触发时间与真实运行；运行删除时置空|
|`last_status`、`last_error_code`|`started` / `skipped` 及稳定错误码|

约束：启用时必须有 `next_run_at` 或 `calendar_waiting_year`；`last_status` 只能为 `started`、`skipped` 或 NULL；归属通过 `(workspace_id, owner_user_id)` 外键绑定 `workspace_memberships`。

## 接口

|方法|路径|说明|
|---|---|---|
|GET|`/api/schedules?offset=0&limit=50`|列出本人当前空间的任务|
|GET|`/api/schedules/{id}`|按 ID 读取本人任务详情，供聊天结果直接打开|
|POST|`/api/schedules`|创建任务，返回 201|
|POST|`/api/schedules/{id}`|完整更新配置；可提交 `revision` 以校验并发编辑，旧客户端省略 `calendar_mode` 时保留原规则|
|POST|`/api/schedules/{id}/enabled`|单独修改启用状态|
|POST|`/api/schedules/{id}/wechat-push`|只切换微信推送，不重算下次 Cron 时间|
|POST|`/api/schedules/{id}/delete`|删除任务，返回 204；已产生对话和运行保留|
|POST|`/api/schedules/{id}/run`|立即触发一次，返回 202 运行快照；不改变原定 Cron|

创建/更新请求：

```json
{
  "name": "每日晨报",
  "prompt": "请总结今天的重点事项。",
  "conversation_id": "UUID",
  "cron_expression": "0 9 * * *",
  "timezone": "Asia/Shanghai",
  "calendar_mode": "all_days",
  "enabled": true,
  "push_to_wechat": false
}
```

错误码：`INVALID_CRON`、`INVALID_TIMEZONE`、`CONVERSATION_NOT_FOUND`、`CONVERSATION_ARCHIVED`、`SCHEDULE_NOT_FOUND`、`SCHEDULE_VERSION_CONFLICT`、`RUN_IN_PROGRESS`、`MODEL_NOT_CONFIGURED`。

## Cron 与时区

- 只接受标准五段：分 时 日 月 周；不接受秒级扩展和 `@daily` 等别名。
- 时区使用 IANA 名称；Windows 依赖项目声明的 `tzdata` 包。
- 服务端按任务时区计算，数据库保存 UTC；列表按任务时区展示。
- 新建任务未提供时区时使用 `EA_SCHEDULE_TIMEZONE`，默认 `Asia/Shanghai`。
- 改动 Cron、时区、日期筛选或启用状态时，从当前时间重新计算；更新任务名称、指令或推送开关保留下次触发时间。
- 日期筛选以北京时间匹配 Cron 候选。`cn_workday` 排除放假和普通周末，包含国务院公告的周末调休上班日。要在调休周末也执行每日任务，使用每日 Cron，如 `30 14 * * *`。
- `cn_a_share` 跳过周末及沪深交易所公告的休市日。「运行一次」是手动触发，可在筛选日期以外执行。调度器重启后遇到休市或休假，当天不会补跑积压。
- 日历数据集中在 `backend/app/services/schedule_calendar.py`。中国法定工作日覆盖 2026、2027 年，沪深休市日覆盖 2026 年。公告发布后补录对应年份并部署。缺少公告时保留启用状态并显示等待的年份，调度器在数据补齐后恢复计算。

## 前端

- 入口：侧边栏“定时任务”或 `/schedules`。
- 表单：名称、固定对话、可视化执行时间、时区、日期筛选、任务指令和启用状态。
- 表单和任务行都提供微信推送开关；列表显示当前推送状态，只有用户主动开启才外发。
- 固定对话支持选择已有对话，或点击“新建对话”立即创建一个对话并选中；保存后会固定使用该对话。
- 执行时间使用内置 `CronBuilder` 组件：可选择每天、每周、每月、固定间隔，也可以切换到“高级 Cron”手写五段表达式；组件实时显示生成的 Cron。
- 列表显示两行以内的指令摘要、任务状态、日期筛选、下次触发和固定对话；「任务详情」显示全文、Cron、时区和最近触发。每页显示 20 条，聊天结果链接可直接打开指定任务并展开详情。
- 新建任务前必须至少有一个活跃对话；没有时可直接在表单中新建，无需先跳转问答页。

## 对话编辑

- 默认助手可用 `list_scheduled_tasks` 找到唯一任务，使用 `get_scheduled_task` 获取详情和配置版本，再用 `update_scheduled_task` 提交明确要修改的字段。
- 自定义 Agent 按配置绑定以上工具；空间管理员可停用工具。编辑沿用逐次审批，写入前重新检查用户、空间、任务归属和版本。
- 修改支持名称、任务指令、Cron、时区、日期筛选、启停与微信推送。固定对话可在任务页编辑。修改会保留任务标识与既有运行记录。

## 微信推送与会话续接

- 任务的 `push_channels` 包含某个渠道、用户已绑定该渠道，并且该渠道允许主动发送时，运行结束后才推送。微信还要处在 iLink 24 小时窗口内；飞书没有这个窗口；钉钉通常需要员工先打开过单聊；QQ 主动消息另有好友和开关限制。没有勾选的渠道不会投递，这不是失败。网页回答始终保留。`push_to_wechat` 只表示微信这一项。
- 推送成功后，渠道账号的当前空间和对端当前对话会切到任务的固定对话；用户随后在微信回复时，消息继续写入这条对话。推送失败或被窗口拦截时不切换，避免劫持微信上下文。
- 启用定时问答后，默认助手可列出、创建、启停任务。创建和启停沿用逐次审批。创建时可选填 `agent_profile_id`，指定本人在当前空间已启用的私有助手。审批卡显示目标助手、Cron、时区、启用状态及微信推送开关。批准时再次校验归属，并在同一事务创建绑定该助手的专用对话和任务。省略该参数时复用当前对话。
- 任务结果链接使用 `/schedules?schedule={id}`，登录后通过 `GET /api/schedules/{id}` 读取本人当前空间的任务。每次触发按目标对话装配当时生效的 Agent 配置，技能使用该 Agent 绑定的具体版本。
- 微信渠道仍是一条物理聊天；多条任务连续推送时，最后一条成功推送的任务成为后续回复上下文。用户可以发送 `/new` 开始新的普通微信对话。

### 基金简报示例

管理员在连接器页面安装并启用“基金行情”后，可以在定时任务问题中直接指定自选基金代码。例如：

> 用基金行情工具查询 ETF 510300 的最近行情、场外基金 110022 的最新披露单位净值和 009033 的当日参考估值。逐项注明数据来源与日期或时间，估值缺失时标注“暂无当日估值”。

选择固定对话和盘后执行时间，再按需开启“推送结果到微信”。可先点“运行一次”确认数据和格式。基金行情源无需订阅，问答和简报仍使用工作台已配置的模型。微信投递沿用现有的绑定和消息窗口要求。参见 [基金行情连接器](连接器系统设计.md#免费基金行情连接器2026-11-18)。

已绑定个人“养基宝持仓”连接器的用户，可以在自己的任务中查询养基宝持仓基金列表，再按基金代码调用行情工具。需要分析仓位、金额或成本时，可使用持仓明细工具 `yangjibao__get_portfolio`。调度沿用任务所有者身份，工具执行前核验绑定，明细作为问答上下文供模型使用。

## 从对话创建任务后的服务重启恢复

迁移 `0025` 为创建定时任务的审批保存完整执行参数，包括审批时的有效时区。公开审批接口仍返回预览。新进程取得问答执行锁后复核运行、成员、空间、目标对话、私有 Agent、工具策略和参数摘要。

同一次工具调用的 UUID 同时作为任务主键。任务、可选的专用对话、审批执行状态和事件在同一 PostgreSQL 事务内提交。服务在提交前退出时可以重新执行；提交后退出时读取原任务，并将链接补到原对话已有回答的末尾。重复恢复使用同一任务 ID。用户另行发起并批准的新请求拥有独立的调用 ID。

恢复范围是本次已批准的创建动作。服务意外退出时，待审批请求会过期，旧版本缺少完整参数的创建请求不会重放。模型的后续推理和其他工具步骤不会重放。已删除的任务不会因恢复而重新创建。

2026-11-23 在独立 PostgreSQL 测试库验收。用例先通过实际审批 API 批准，再分别在业务创建前、业务已提交时关闭旧运行实例，并让新实例从正式初始化入口恢复。另行验证两个事务同时执行同一审批、空间停用工具、参数摘要不匹配，以及超出预览长度的问题全文保留。检查覆盖任务数量和 ID、审批事件、工具调用结果、原回答状态和链接。

### 停止回答期间的任务状态

停止和创建使用同一条运行记录的数据库行锁，以事务提交顺序决定结果。停止先提交时，审批和工具调用均记为已取消。任务先提交时，停止只结束回答，原对话保留已生成文字、创建成功的工具记录及任务链接。如果停止时任务已删除，回答会说明删除结果，工具记录保留当次创建成功的事实并隐藏失效入口。若停止请求落库后服务退出，新实例沿用同一套终态处理；重复停止不追加审批事件。

专项测试通过 PostgreSQL 覆盖在线停止、停止落库后替换运行实例、迟到的工具失败回调和任务删除场景。可在 backend 目录运行：

~~~bash
uv run pytest --no-cov tests/test_approvals_integration.py
~~~
