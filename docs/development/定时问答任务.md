# 定时问答任务

日期：2026-11-11。状态：已实现（本地单进程范围）。迁移 `0009`。

## 能力与边界

- 按五段 Cron 向一个**固定对话**追加新的问答 Run；结果继续走现有 SSE、历史记录、停止与重试链路。
- 创建任务时可以直接新建一个对话并固定使用，也可以选择已有对话。
- 复用现有规划、只读工具和单层子 Agent，不新增第二套 Agent 执行链路。
- 支持创建、列表、完整编辑、启停、删除和“运行一次”。
- 不创建新对话；多次触发会按消息序号累积在同一对话中，并受现有上下文压缩策略约束。
- 同一对话已有活跃运行时，本次触发记录为 `skipped`，不会排队或补跑。
- 错过的多次触发只保留最近一次，不补跑积压；服务重启后已提交运行按现有问答规则收敛。
- 不支持独立 Worker、跨进程调度、通知推送和任意图节点续跑。

## 架构

```text
Vue SchedulesView
  → /api/schedules（CRUD / run）
  → ScheduleRuntime（单进程轮询 + PostgreSQL advisory lock 782341917）
  → ScheduleStore.claim_due（SKIP LOCKED，先推进 next_run_at）
  → ChatRuntime.store.create_run（固定对话、幂等键）
  → ChatRuntime.schedule（现有真实问答生成）
```

- `ScheduledTask` 只保存定义、固定对话和最近一次触发结果；消息与运行仍保存在原有 `messages`、`runs` 表。
- 调度器与问答执行器分别持锁，但调度器在领取前调用 `ChatRuntime.ensure_ready()`；重复后端进程不会执行定时任务。
- `claim_due` 在同一个事务内使用 `SELECT ... FOR UPDATE SKIP LOCKED`，先写入下一次触发时间；进程在创建运行前崩溃时最多丢失一次触发，不会重复执行。
- 幂等键格式为 `schedule_{id}_{触发时间}`；同一触发重复创建运行会返回已有快照。
- 触发时重新校验账号、空间成员、对话归属和对话状态；撤权或归档只记录跳过，不创建运行。

## 数据模型

|字段|说明|
|---|---|
|`workspace_id`、`owner_user_id`|可信归属；外部请求不能指定|
|`conversation_id`|固定结果对话；删除对话时级联删除任务|
|`name`、`prompt`|公开名称与到期提交的问题|
|`cron_expression`、`timezone`|五段 Cron 与 IANA 时区|
|`enabled`、`next_run_at`|启用状态与下一次 UTC 触发时间；停用时为 NULL|
|`last_run_at`、`last_run_id`|最近一次触发时间与真实运行；运行删除时置空|
|`last_status`、`last_error_code`|`started` / `skipped` 及稳定错误码|

约束：启用时必须有 `next_run_at`；`last_status` 只能为 `started`、`skipped` 或 NULL；归属通过 `(workspace_id, owner_user_id)` 外键绑定 `workspace_memberships`。

## 接口

|方法|路径|说明|
|---|---|---|
|GET|`/api/schedules?offset=0&limit=50`|列出本人当前空间的任务|
|POST|`/api/schedules`|创建任务，返回 201|
|POST|`/api/schedules/{id}`|完整更新名称、问题、对话、Cron、时区、启用状态|
|POST|`/api/schedules/{id}/delete`|删除任务，返回 204；已产生对话和运行保留|
|POST|`/api/schedules/{id}/run`|立即触发一次，返回 202 运行快照；不改变原定 Cron|

创建/更新请求：

```json
{
  "name": "每日晨报",
  "prompt": "请总结今天的重点事项。",
  "conversation_id": "UUID",
  "cron_expression": "0 9 * * *",
  "timezone": "Asia/Shanghai",
  "enabled": true
}
```

错误码：`INVALID_CRON`、`INVALID_TIMEZONE`、`CONVERSATION_NOT_FOUND`、`CONVERSATION_ARCHIVED`、`SCHEDULE_NOT_FOUND`、`RUN_IN_PROGRESS`、`MODEL_NOT_CONFIGURED`。

## Cron 与时区

- 只接受标准五段：分 时 日 月 周；不接受秒级扩展和 `@daily` 等别名。
- 时区使用 IANA 名称；Windows 依赖项目声明的 `tzdata` 包。
- 服务端按任务时区计算，数据库保存 UTC；前端按浏览器本地时间展示。
- 新建任务未提供时区时使用 `EA_SCHEDULE_TIMEZONE`，默认 `Asia/Shanghai`。
- 编辑任务时始终从当前时间重新计算下一次触发；停用会清空 `next_run_at`。

## 配置

|变量|默认值|说明|
|---|---|---|

|`EA_SCHEDULE_POLL_SECONDS`|5|轮询间隔，(0,60] 秒|
|`EA_SCHEDULE_TIMEZONE`|Asia/Shanghai|默认 IANA 时区|

## 前端

- 入口：侧边栏“定时任务”或 `/schedules`。
- 表单：名称、固定对话、可视化执行时间、时区、定时问题、是否启用。
- 固定对话支持选择已有对话，或点击“新建对话”立即创建一个对话并选中；保存后会固定使用该对话。
- 执行时间使用内置 `CronBuilder` 组件：可选择每天、每周、每月、固定间隔，也可以切换到“高级 Cron”手写五段表达式；组件实时显示生成的 Cron。
- 列表：Cron/时区、下次触发、最近触发与状态、固定对话链接；支持运行一次、编辑、启停、删除。
- 新建任务前必须至少有一个活跃对话；没有时可直接在表单中新建，无需先跳转问答页。
