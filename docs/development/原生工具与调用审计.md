## 已实现范围

get_my_run_stats 查询本地真实问答记录。模型可在普通问答中按需调用，不创建业务任务，不需要预算字段。默认启用，普通知识问答仍可直接回复。MCP 尚未实现；知识库检索已在 2026-11-11 作为独立工具接入。

使用问题：**请查询我在当前空间最近 7 天的运行统计，说明各状态数量。** 回答下方展开“工具调用记录”查看实际执行状态和聚合结果。模型是否选择调用由模型决定；没有调用记录时，不能把回答当作已经查库的证据。

## 请求与执行流程

1. 已登录用户通过原问答接口创建 Run，服务端绑定用户和空间。
2. 每次生成创建独立 DeepSeekProvider 与 ToolExecutor；不在全局模型实例上修改身份或工具状态。
3. Deep Agents 的模型中间件只暴露 get_my_run_stats；返回其他工具名立即失败。工具中间件再次检查白名单，直接进入统一执行入口，不委托 SDK 内置文件、命令或子 Agent 工具执行。
4. ToolExecutor 从 Run → Conversation 读取可信身份，复核 active 账号/成员/空间/对话，以及运行 running 且未请求取消。
5. 锁定 Run 后检查持久化调用次数，创建审计，再校验参数、执行只读聚合。每一步使用独立短事务，不共用 AsyncSession。
6. 成功发布前复核权限，保存聚合结果，返回工具消息让模型生成回答；正文仍沿原 SSE 推送。
7. 前端按需展开读取审计；只有展开且生成中时约每秒刷新，关闭或卸载停止刷新。

摘要使用独立无工具调用，原始消息与压缩边界保持不变。SDK 自带工具是叠加注册的，仅传 tools 不代表移除了内置能力，所以同时限制模型入口和执行入口。实现依据已锁定 SDK 源码，并用真实 SDK 图与模拟 HTTP 测试执行路径。参考 [Deep Agents 官方实现](https://github.com/langchain-ai/deepagents/blob/main/libs/deepagents/deepagents/graph.py)。

## 工具契约与授权

- 标识：get_my_run_stats。
- 参数：days，严格整数，1–90，默认 7。拒绝额外字段及字符串数字。
- 不接受 user_id、workspace_id、SQL 或资源路径；管理员同样只能查自己。
- 统计条件：Conversation.created_by_user_id=当前用户，workspace_id=当前空间，Run.created_at 在滚动 days 天内。
- 返回 days、total、counts；counts 包含 pending/running/completed/failed/cancelled。**包含本次正在执行的运行**，统计不是全空间总量，也不是业务任务数量。
- 不读取消息正文或摘要。聚合结果是查询时点快照，不承诺之后各状态不变。
- 本阶段没有按成员配置工具授权的管理界面；所有有效成员采用同一只读规则，角色不会扩大数据范围。

## 配置

|配置|默认|含义|
|---|---|---|
|EA_TOOLS_ENABLED|true|关闭后模型不提供工具；尝试工具调用会失败|
|EA_TOOL_TIMEOUT_SECONDS|5|单次实际查询超时，范围 (0,30] 秒；不含审计提交与模型生成|
|EA_TOOL_MAX_CALLS_PER_RUN|4|每个运行最多执行查询的次数，范围 1–10；失败尝试也计数|

后台仍受总模型生成超时约束。达到调用上限后保留失败审计，但不执行查询；审计条数可以超过实际执行上限。模型重复请求还受图递归上限约束。没有自动重试或业务写入。

## 审计模型与接口

新增 tool_calls，外键 run_id 关联 Run，权限经 Run → Conversation 继承。字段：id、run_id、tool_name、days、status、result、error_code、created_at、finished_at；状态 running/completed/failed/cancelled，终态必须有 finished_at。

只保存合法 days 和结构化聚合结果，不保存模型原始任意参数、密码、Cookie、问题或消息。错误结果不保存查询结果。未授权工具名在执行前被拦截，不执行、也不生成工具审计；Run 保留 TOOL_NOT_ALLOWED 失败码。执行前已撤权时直接拒绝，不建立新审计。

GET /api/runs/{run_id}/tool-calls：Cookie + X-Workspace-ID，归属不存在返回 404，无登录 401，无成员权限 403。响应为按调用时间排列的 ToolCallView 数组，含安全聚合结果 JSON 字符串。管理员不能访问别人。该接口为读取，不需要 CSRF。

错误：TOOL_INVALID_ARGUMENTS、TOOL_TIMEOUT、TOOL_CALL_LIMIT、TOOL_EXECUTION_FAILED 返回明确 ok=false；撤权使整个 Run 失败并丢弃未发布结果。取消生成中断工具，审计 cancelled；重启收敛未完成记录为 failed/PROCESS_RESTARTED。数据库不可用导致审计提交失败时不把查询显示成成功。

审计随 Run 的受信物理删除级联删除；当前不提供网络删除 Run 的接口。长期审计保留策略待工程加固阶段明确。

## 迁移、验证与使用

已有后端停止后执行（backend 目录）：

~~~bash
uv run alembic upgrade head
uv run alembic check
~~~

开发库仅升级，0006 不修改原问答/身份数据。测试库迁移往返由自动测试执行，不能对开发库降级。0006 降级会丢失工具审计，因此不作为正常回滚手段。

项目根目录 python scripts/start.py 同时启动前后端；登录后发送统计问题，展开调用记录；刷新后仍可读取审计。

自动验收：node scripts/check.mjs --database，数据库测试上限调整为 5 分钟。真实模型独立验证：backend 目录 uv run python -m scripts.verify_real_tools；仅使用专用测试库，创建随机账号，真实调用 DeepSeek，验证审计与统计，再按本次 ID 清理，可能产生两轮模型请求费用。不要与数据库迁移测试并行执行。

详细证据见阶段四验收记录。自动测试的供应商 HTTP 是受控替身，不能代替真实模型成功的结论；浏览器视觉验收需单独记录。
