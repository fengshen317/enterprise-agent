# 连接器（Connector）系统设计 — 对标 WorkBuddy

> **状态**：已实现（步骤 1-7 完成）
> **日期**：2026-11-12
> **需求来源**：对标 WorkBuddy 的"连接器"页面，支持 CLI / MCP / API 三种集成模式

## 一、WorkBuddy 连接器架构分析

WorkBuddy 的"连接器"本质是**三种集成模式的统一抽象**：

| 模式 | 示例 | 技术原理 |
|---|---|---|
| **CLI 连接器** | 腾讯会议、钉钉、企业微信 | 封装命令行工具，`subprocess` 调用 |
| **MCP 连接器** | 通达信、天眼查 | MCP 协议（JSON-RPC），自动发现工具 |
| **API 连接器** | QQ邮箱、腾讯文档 | 直接调 REST API |

核心设计特征：
1. **统一工具抽象**：不管底层是 CLI/MCP/API，最终都暴露为"工具"给 Agent
2. **连接器市场**：卡片式展示，用户可浏览、启用、配置
3. **自定义连接器**：用户可自定义新连接器
4. **状态管理**：每个连接器有连接状态（已连接/未配置/错误）

## 二、MCP 协议简介

MCP (Model Context Protocol) 是 Anthropic 的标准协议（类似 USB 接口）：
- **MCP Server**：暴露 tools / resources / prompts（定义 `name` + `description` + `inputSchema`）
- **MCP Client**：`list_tools()` 发现工具，`call_tool()` 调用工具
- **传输**：stdio（子进程）、SSE/HTTP（远程服务）
- **Python SDK**：`mcp` 包（需安装）

**分层原则**：连接器层只做"外部工具 → ToolSpec"的翻译；身份、审批、审计、配额、装配全部交给现有能力层。

## 四、核心接口定义

新目录 `backend/app/connectors/`：

```python
# base.py
ConnectorKind = Literal["cli", "mcp", "api"]
ConnectorStatus = Literal["disabled", "connected", "degraded", "error"]

class Connector(Protocol):
    key: str                    # 稳定标识
    kind: ConnectorKind

    def config_fields(self) -> tuple[ConfigField, ...]:
        """声明配置项（含是否密钥），前端渲染 + 校验。"""

    async def connect(self) -> ConnectorStatusInfo:
        """建立会话/健康检查。"""

    async def list_tools(self) -> list[ConnectorToolDef]:
        """发现工具：MCP 走 list_tools()；CLI/API 为声明式定义。"""

    def tool_specs(self, defs, policy) -> list[ToolSpec]:
        """把工具定义映射为 ToolSpec。"""

    async def call(self, name: str, arguments: dict) -> object:
        """执行一次外部调用。"""

    async def aclose(self) -> None:
        """释放资源。"""
```

### 关键扩展点

**ToolSpec 增量改动**（`capabilities/spec.py`）：
- `source: Literal["builtin", "connector"] = "builtin"`
- `connector_key: str | None = None`
- `input_schema_override: dict | None = None`（MCP 原始 schema 直出）

**ToolRegistry 增量**（`capabilities/registry.py`）：
- `replace_group(connector_key, specs)` — 连接器热更新时替换工具组
- `unregister(key)` — 移除连接器工具

**动态 args_model 生成**（`dynamic_args.py`）：
- MCP 工具的 JSON Schema → 动态 pydantic 模型
- 简单类型显式字段，嵌套降级为 Any

## 八、与现有 ToolSpec 系统的关系

| 关注点 | 结论 |
|---|---|
| 执行链路 | **完全复用**，连接器工具 = 普通 ToolSpec |
| 装配 | AgentAssembler 按 key resolve，自动兼容 |
| 子 Agent | 自动生效（external 工具天然被排除） |
| 空间启停 | WorkspaceToolPolicy 按 key 生效 |
| 审计 | ToolCall 记录连接器工具 key + 脱敏摘要 |

## 十、关键优势

- **零侵入现有架构**：连接器只做"翻译"，能力层完全复用
- **三种模式统一**：CLI / MCP / API 都产出 ToolSpec
- **热更新**：配置修改即生效，无需重启
- **扩展性**：新增连接器 = 实现 Connector 协议 + 注册
- **MCP 标准兼容**：可接入任何 MCP Server（通达信、天眼查等）
