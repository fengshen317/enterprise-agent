# 连接器（Connector）系统设计 — 对标 WorkBuddy

> **状态**：已实现（步骤 1-7 完成）
> **日期**：2026-11-12
> **需求来源**：对标 WorkBuddy 的"连接器"页面，支持 CLI / MCP / API 三种集成模式

## 一、WorkBuddy 连接器架构分析

WorkBuddy 的"连接器"本质是**三种集成模式的统一抽象**：

| 模式 | 示例 | 技术原理 |
|---|---|---|
| **CLI 连接器** | 腾讯会议、钉钉、企业微信 | 封装命令行工具，`subprocess` 调用 |
| **MCP 连接器** | 通达信、天眼查 | MCP 协议（JSON-RPC），自动发现工具 |
| **API 连接器** | QQ邮箱、腾讯文档 | 直接调 REST API |

核心设计特征：
1. **统一工具抽象**：不管底层是 CLI/MCP/API，最终都暴露为"工具"给 Agent
2. **连接器市场**：卡片式展示，用户可浏览、启用、配置
3. **自定义连接器**：用户可自定义新连接器
4. **状态管理**：每个连接器有连接状态（已连接/未配置/错误）

## 二、MCP 协议简介

MCP (Model Context Protocol) 是 Anthropic 的标准协议（类似 USB 接口）：
- **MCP Server**：暴露 tools / resources / prompts（定义 `name` + `description` + `inputSchema`）
- **MCP Client**：`list_tools()` 发现工具，`call_tool()` 调用工具
- **传输**：stdio（子进程）、SSE/HTTP（远程服务）
- **Python SDK**：`mcp` 包（需安装）

## 四、核心接口定义

新目录 `backend/app/connectors/`：

```python
# base.py
ConnectorKind = Literal["cli", "mcp", "api"]
ConnectorStatus = Literal["disabled", "connected", "degraded", "error"]

class Connector(Protocol):
    key: str                    # 稳定标识
    kind: ConnectorKind

    def config_fields(self) -> tuple[ConfigField, ...]:
        """声明配置项（含是否密钥），前端渲染 + 校验。"""

    async def connect(self) -> ConnectorStatusInfo:
        """建立会话/健康检查。"""

    async def check_health(self) -> ConnectorStatusInfo:
        """检查当前实例的连接与认证状态。"""

    async def list_tools(self) -> list[ConnectorToolDef]:
        """发现工具：MCP 走 list_tools()；CLI/API 为声明式定义。"""

    def tool_specs(self, defs, policy) -> list[ToolSpec]:
        """把工具定义映射为 ToolSpec。"""

    async def call(self, name: str, arguments: dict) -> object:
        """执行一次外部调用。"""

    async def aclose(self) -> None:
        """释放资源。"""
```

### 关键扩展点

### 腾讯会议认证与失败处理（2026-11-17 修复）

- 微信绑定只建立消息渠道；腾讯会议查询还需要后端运行账号完成 `tmeet` OAuth 登录。
- CLI 可执行文件优先从项目 `tools/node_modules/.bin` 解析，再查系统 PATH。
- 腾讯会议健康检查依次执行 `--version` 和 `auth status`。`auth status` 未登录时仍可能退出码为零，必须识别文本状态；未登录显示“请完成账号授权”，不再展示连接正常。其他 CLI 仍使用原有版本检查。
- `auth_status` 工具返回结构化 `logged_in` 状态；不把账号标识、Token 状态文本回传模型，也不对 CLI 的文本状态强行解析 JSON。
- CLI 命令模板里的可选 `--option {value}` 在值为 `None` 时整组省略，保留 CLI 自带的默认时间窗口；显式传入的查询条件和默认分页参数保持不变。
- 工具执行层只公开白名单错误码和固定中文提示，不向模型或审计透传原始 stderr：

| 底层分类 | 工具错误码 | 处理建议 |
|---|---|---|
| `not_logged_in` | `CONNECTOR_NOT_LOGGED_IN` | 在后端运行账号下完成账号授权后重试 |
| `permission_denied` | `CONNECTOR_PERMISSION_DENIED` | 检查账号授权范围 |
| `timeout` | `TOOL_TIMEOUT` | 稍后重试 |
| `invalid_output` | `CONNECTOR_INVALID_OUTPUT` | 检查 CLI 版本和返回格式 |
| `command_failed` | `CONNECTOR_COMMAND_FAILED` | 检查连接器状态和配置 |
| 未知异常或分类 | `TOOL_EXECUTION_FAILED` | 保持通用错误，避免泄露内部信息 |

### 持续监控与授权提醒（2026-11-18）

后台在启动时检查已启用连接器，随后每 60 秒探测一次。`ConnectorRegistry` 复用现有实例执行健康检查，每个连接器独立超时。同一连接器的并发检查共享结果，配置更新与检查按连接器串行执行。真实工具调用成功或失败后也会立即更新状态。实例更新前发起的迟到结果会被忽略。

页面通过共享 Pinia Store 每 15 秒读取状态，隐藏标签页暂停轮询，重新显示时刷新。登录用户和工作空间切换后清理旧状态并忽略旧响应。全局持续提醒列出需要授权或配置的已启用连接器。管理员可跳转到对应配置抽屉，普通成员看到联系管理员提示。连接器停用后停止探测并清除待处理操作。

认证状态与连接状态独立记录。网络或 DNS 失败将认证标记为待确认，保留上次成功时间。只有明确的未登录、缺失密钥或 401 才提示授权或配置。

| 字段 | 含义 |
|---|---|
| `status` | 原有 `disabled/connected/degraded/error` 连接状态 |
| `auth_status` | `unknown/authorized/required/not_required` 认证结果 |
| `auth_action` | 服务端推导的 `authorize/configure/retry` 操作，正常或停用时为空 |
| `last_error_code` | 固定公开错误分类 |
| `last_checked_at` | 最近检查或工具调用反馈时间 |
| `last_success_at` | 最近成功检查或工具调用时间，失败时保留 |

迁移 `0018` 为 `connectors` 增加 `auth_status`、`last_error_code`、`last_success_at`，复用原有检查时间和错误信息列。旧数据的认证状态默认为 `unknown`，启动检查确认后更新。迁移完成后的就绪版本为 `18`。

#### 各类连接器的检查方式

- 腾讯会议 CLI 执行版本检查和 `auth status`，识别未登录的零退出码及刷新期间的网络错误。已确认授权时点击授权直接返回成功。
- API 连接器先检查必需密钥，再使用可选 `health_path` 发起 GET 请求验证。路径必须是当前 `base_url` 下以 `/` 开头的相对路径。健康请求使用配置的认证头和前缀，管理员应选择服务提供的只读、无计费探测接口。
- API 未配置健康路径时显示待确认，实际业务调用成功可确认连接与认证。401 提示更新凭证，403 提示检查权限。配置页保存的密钥从 `integration_configs` 注入后端实例，内置 Tavily 兼容原有 `EA_TAVILY_API_KEY` 配置。
- MCP 通过现有会话发送 ping，并对 SDK 包装的 HTTP 401 进行分类。单纯 ping 成功时，认证状态仍为未知，业务调用成功后确认认证。

#### 授权进程生命周期

`POST /api/admin/connectors/{key}/auth` 对腾讯会议创建或复用一个后台登录流程。取得官方授权链接后及时返回，首次最多等待 8 秒，后台保留最多 5 分钟等待扫码。进行中的并发请求共享流程。页面提供授权链接，每 2 秒串行读取授权进度，结束后执行健康复查并刷新全局提醒。

授权 URL 只接受 `https://meeting.tencent.com/marketplace/tencentmeeting-cli-auth.html` 和非空授权码，原始 CLI 输出不会回传客户端。URL 出现分段输出时，等待完整链接再公开。配置更改、停用和服务关闭会回收该流程拥有的进程树及输出线程。服务重启后，前端通过状态复查确认是否已经授权。

认证与授权接口保持管理员权限，授权进度响应禁止缓存。前端健康检查请求允许 65 秒，授权启动允许 90 秒，以覆盖后端可配置检查超时及获取链接的等待时间。

| 配置项 | 默认值 | 范围 |
|---|---|---|
| `EA_CONNECTOR_MONITOR_ENABLED` | `true` | 是否启用后台定时检查 |
| `EA_CONNECTOR_MONITOR_INTERVAL_SECONDS` | `60` | 1 至 3600 秒 |
| `EA_CONNECTOR_CHECK_TIMEOUT_SECONDS` | `15` | 大于 0 且不超过 60 秒 |

部署或更新时先在 `backend/` 执行 `uv run alembic upgrade head`，随后启动后端。数据库中的检查结果仅含状态和固定提示，账号凭证仍由原有密钥存储管理。

本次真实配置验证中，腾讯会议检查结果为 `connected/authorized`，启动监控后检查时间持续推进。Tavily 已配置密钥但缺少只读健康路径，结果为 `degraded/unknown`。自动化测试使用受控进程验证授权等待、到期、关闭与进程树清理，HTTP 集成测试验证管理员权限及状态契约，真实数据库测试验证检查持久化和并发停用。新后台授权流程的真实扫码端到端验收仍待进行，现有账号保持已授权。

最终检查结果为后端 397 项通过、4 项已有 SDK 集成用例失败，总体覆盖率 80.09%。失败项与 2026-11-17 基线核对结果一致。前端 32 个测试文件共 131 项全部通过，lint、TypeScript 类型检查和生产构建通过。后端 `ruff check .` 和 `mypy app/` 通过。迁移 `0018` 已在当前开发库执行，后端就绪检查通过。总体测试仍有失败，阶段补充项保留待全量验收状态。

## 十、关键优势

- **零侵入现有架构**：连接器只做"翻译"，能力层完全复用
- **三种模式统一**：CLI / MCP / API 都产出 ToolSpec
- **热更新**：配置修改即生效，无需重启
- **扩展性**：新增连接器 = 实现 Connector 协议 + 注册
- **MCP 标准兼容**：可接入任何 MCP Server（通达信、天眼查等）
