## 本地问答链路

Vue 问答页 → FastAPI → ChatStore 原子创建用户消息、Run 和助手占位 → ChatRuntime 持有异步任务 → Deep Agents 图 → DeepSeek 官方 API → 批量覆盖助手正文 → 提交终态。浏览器通过 SSE 读取持久化快照。

职责分布：

- app/schemas/chat.py：请求与响应结构、输入限制。
- app/services/chat_store.py：短事务、锁行、序号、幂等和状态写入。
- app/services/chat_runtime.py：单进程排他、生成任务引用、取消、超时与退出。
- app/agents/provider.py：Deep Agents + ChatDeepSeek 适配；测试可以注入 StreamProvider。
- app/api/chat.py：HTTP 与 SSE，不在路由里直接拼接 SDK 调用。
- frontend/src/api/chat.ts：接口运行时校验、SSE 订阅和关闭。
- frontend/src/views/ChatView.vue：新对话、历史、追问、状态、停止与失败重试。

## 依赖与模型

锁文件当前包含 deepagents 0.7.32、langchain-deepseek 1.1.1、LangGraph 1.2.19。使用 create_deep_agent 和 stream_mode=messages，过滤主模型的正文块，不展示推理内容。

默认模型 deepseek-flash，官方地址固定为 https://api.deepseek.com。EA_DEEPSEEK_MODEL 可替换模型标识；本次真实调用验证的是该默认模型。普通问答关闭 thinking。模型请求显式移除工具 schema，并拦截模型仍返回工具调用的情况；不启用本机文件系统、命令执行、MCP 或业务写入。每次运行独立建图和模型客户端，退出流时释放客户端。SDK 暂不配置持久化 checkpointer，历史由 PostgreSQL 业务消息重建；检查点恢复在阶段五实现。

依据：[Deep Agents 构造说明](https://github.com/langchain-ai/deepagents/blob/main/libs/ARCHITECTURE.md)、[DeepSeek 官方接口](https://api-docs.deepseek.com/api/create-chat-completion)。版本以 uv.lock 为准。

## 接口

所有业务接口现已要求 Cookie、工作空间及资源归属校验，写操作还要求 Origin 和 CSRF。当前仍仅按本机开发运行。错误沿用 error.code、error.message、request_id。

|方法|路径|行为|
|---|---|---|
|POST|/api/conversations|201 创建对话，body 为 title（默认 新对话，1–200 字符）|
|GET|/api/conversations|200 对话数组，offset>=0、limit=1–100，默认 50，按 updated_at/id 递减|
|GET|/api/conversations/{id}/messages|200 消息页，after_sequence>=0、limit=1–200，默认 100，按序号递增|
|POST|/api/conversations/{id}/runs|202 创建或返回已有运行，body 为 content 与 idempotency_key|
|GET|/api/runs/{id}|200 最新运行及助手消息快照|
|GET|/api/runs/{id}/events|200 text/event-stream，完整快照与终态|
|POST|/api/runs/{id}/cancel|200 幂等停止并返回收敛后的快照|

content 为 1–20000 字符且不能全空白。idempotency_key 为 1–100 个英文字母、数字、下划线或短横线。不存在的资源返回 404，格式错误返回 422。创建运行前检查密钥是否配置；没有密钥仍可创建空对话、查看历史，但提交问题返回 503 MODEL_NOT_CONFIGURED。

请求示例：

~~~json
{"content":"请解释 Agent 中 Tool 和 MCP 的关系","idempotency_key":"example-001"}
~~~

消息页形状：

~~~json
{"items":[],"has_more":false,"active_run_id":null}
~~~

RunSnapshot 形状：run 含 id、conversation_id、status、model、input_sequence、公开错误及各执行时间；message 含消息标识、对话/运行关联、sequence、role、content、status 和创建/更新时间。精确 JSON Schema 可在 /docs 查看。

## 幂等与事务

创建运行锁定 Conversation，先查同对话幂等键，再检查未结束运行，随后分配两个连续消息序号，在一个事务中创建用户输入、Run、助手占位并推进计数。首次问题自动替换默认标题。相同键、相同原始 content 返回已有运行；相同键、不同 content 返回 409 IDEMPOTENCY_CONFLICT。另一个运行尚未结束时返回 409 RUN_IN_PROGRESS。

前端提交遇到网络异常时保留原问题和幂等键，再次发送相同问题复用该键，避免响应丢失造成重复生成。刷新页面后丢失尚未确认的本地提交键，通过已持久化历史/当前运行恢复可见状态。

数据库操作各用独立 AsyncSession，模型调用和 SSE 等待期间不持有事务。正文每收到至少 256 字符，或新片段到达且距上次保存超过 150ms 时覆盖保存；结束时保存最后不足一批的内容。它是按片段触发的批量策略，不是严格每 150ms 定时写库。硬崩溃最多丢失尚未保存的批次。

## 状态与上下文

Run：pending → running → completed / failed / cancelled。pending 也可能直接失败或取消。Message：用户始终 completed；助手从 streaming 转为 completed 或 interrupted。失败/取消保留已收到内容；重试须使用新幂等键，创建新尝试。

上下文包含已完成运行的用户与助手消息，以及当前用户问题；失败/取消的用户-助手回合不进入下一次模型上下文。默认上下文硬上限 100000 字符，达到 70% 时自动将较早成功回合压缩为持久化摘要，优先保留最近最多 4 轮；预算不足时减少保留轮数。摘要、游标与版本保存在 Conversation，原始消息不变。摘要加当前问题仍超上限时明确失败，不静默裁剪。详见 [对话上下文压缩](对话上下文压缩.md)。默认正文上限 40000 字符、生成 token 上限 4096。模型报告 finish_reason=length 时保存部分回答并返回 MODEL_OUTPUT_TRUNCATED，不标成完整成功。

取消先持久化 cancel_requested_at，再取消协程，最后在锁下提交终态。取消请求先提交时，完成路径也会改为 cancelled；完成事务先提交时，之后取消保持 completed。协程还没开始时取消同样会收敛，重复取消终态无副作用。

## SSE 与恢复

每 250ms 查询一次持久化快照，仅变化时发送；约每 10 秒发送注释心跳。每次查询后会话立即释放。响应禁用缓存和代理缓冲。

~~~text
event: snapshot
data: {"run":{...},"message":{...}}

event: completed
data: {"run":{...},"message":{...}}
~~~

运行未结束时事件名为 snapshot；终态为 completed / failed / cancelled。每个事件都包含完整累计正文，前端按 message.id 覆盖；终态后关闭订阅。没有 delta 事件、增量事件表或序号回放。重连会立即得到数据库最新快照，不依赖 Last-Event-ID；因此可能跳过中间动画，但最终内容不会重复拼接。EventSource 自动重连，页面还提供手动重新连接。

页面路由 /chat/{conversation_id} 可刷新恢复。读取历史时逐页加载，通过 active_run_id 重新订阅当前运行。离开页面只关闭订阅，不取消生成。UI 将正文按 Markdown 渲染：先由 marked 转换为 HTML，再由 DOMPurify 白名单清洗；禁止脚本、事件属性、内联样式、图片和表单元素，外部链接使用新窗口和 `noopener noreferrer`。原始消息文本仍原样保存在数据库。2026-11-11 修复正文展示，快速检查见 [Markdown 渲染检查](verification/2026-11-11-markdown-checks.txt)。

## 进程生命周期与限制

仅支持一个本机执行进程，不使用 --workers 多进程参数。首次问答访问取得同数据库 PostgreSQL 会话级 advisory lock；第二个进程访问问答返回 503 SINGLE_PROCESS_REQUIRED。持锁进程首次访问时，将上次遗留 pending/running 设为 failed / PROCESS_RESTARTED，消息保留并标 interrupted。健康接口不主动访问业务表或初始化执行器。

正常退出先停止并收敛本进程运行，再释放排他锁与连接池。强制退出后，下次问答访问触发恢复，不自动重放真实调用。数据库重启后需要重启后端，重新建立执行器排他锁；本阶段没有跨进程租约与自动故障接管。

此实现不是持久化任务队列。运行提交后进程立即崩溃或写入数据库期间故障，遗留运行由后端重启后的恢复流程收敛；暂不提供自动重试或自动继续生成。队列、Worker、检查点和更完整故障恢复在阶段五实现。

## 日志与错误

日志只记录 request_id、run_id、状态相关事件和异常类型，不记录问题、回复、密钥或模型异常正文。外部调用异常映射为 MODEL_CALL_FAILED；压缩失败为 CONTEXT_COMPRESSION_FAILED；超时为 MODEL_TIMEOUT；空回答为 EMPTY_MODEL_RESPONSE；上下文/正文过长分别为 CONTEXT_TOO_LONG / OUTPUT_TOO_LONG；工具请求为 TOOLS_DISABLED。

普通问答不会创建业务任务，不提供预算字段。工作空间与用户隔离已在阶段三接入；管理员不自动拥有读取他人私有对话的权限。
