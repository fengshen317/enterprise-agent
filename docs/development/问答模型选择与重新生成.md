# 问答模型选择、上下文用量与重新生成

日期：2026-11-13。状态：已实现。

## 模型选择

允许的模型来自白名单，默认 `deepseek-flash`、`deepseek-chat`、`deepseek-reasoner`。可用 `EA_ALLOWED_MODELS`、`EA_REASONER_MODELS` 和 `EA_MODEL_MAX_TOKENS_BY_MODEL` 调整。每个模型有自己的 `max_tokens`：flash 4096、chat 8192、reasoner 16384。全局 `EA_MODEL_MAX_TOKENS` 只作为未单列模型的默认值。

实际调用顺序是：对话上的 `conversations.model`，否则 Agent 档案中且仍在白名单内的模型，否则 `EA_DEEPSEEK_MODEL`。对话上的显式选择若不在白名单内，接口返回 `MODEL_NOT_ALLOWED`。`runs.model`、助手消息上的 `messages.model` 和该次 `agent_snapshot.model` 记录的是这次真正使用的模型。`DeepSeekProvider` 的回答和子 Agent 都使用这次运行的模型，不再读取全局默认值。

`reasoner_models` 中的模型打开 `thinking`。思考过程写入 `messages.reasoning`，问答页放在可折叠的「思考过程」里。正文仍只在 `content`。摘要始终关闭思考；若本轮模型是推理模型，摘要改用白名单中的第一个非推理模型。因此摘要不会收录思考过程。

问答页右上角是模型下拉框，生成过程中禁用。每条助手消息显示自己的模型名。`GET /api/models` 返回白名单。`POST /api/conversations/{id}/model` 在没有活跃运行时更新对话级选择。

## 上下文用量

压缩阈值仍然按字符计算。自动检索文本和上一轮已完成的计划、子 Agent 资料先算进预算，再决定是否压缩，然后再拼进当前问题。页面上的用量条写明「按字符估算，不是精确 token」。有供应商输入 token 时，额外显示「上次实际输入约 N tokens」。

压缩进行中，运行 `phase` 为 `compressing`，结束后回到 `generating`，终态清空。问答页在状态行和正在生成的消息上显示「正在整理更早的对话」。

## 重新生成与编辑重发

`POST /api/messages/{id}/regenerate` 只接受最近一条助手消息。它新建一条 Run，沿用原来的用户消息和序号，把旧回答归档到原 Run 的 `archived_content` / `archived_reasoning`，并让原来的助手消息指向新 Run。消息列表不会多出一条相同的用户问题。

`POST /api/messages/{id}/edit` 只接受最近一条用户消息，且它后面只能有对应的那条助手回答。新正文写回这条用户消息，旧正文留在 `archived_prompt`，然后按同样的方式替代回答。

已被成功替代的 Run 不再进入后续上下文或摘要。如果替代运行失败、被取消或在重启时被收敛，可见消息会指回原来的运行，原来的问题和回答继续留在上下文里。失败、取消且没有可恢复前序的回合仍然不进入上下文。幂等键仍按对话唯一：同键同内容返回已有运行，同键不同内容返回 `IDEMPOTENCY_CONFLICT`。已经写入历史摘要的回合返回 `SUMMARY_COVERS_TURN`。更早的回合返回 `NOT_LAST_TURN`。

## 引用来源

自动检索得到的来源按消息分别保存。来源卡片的锚点是 `source-{消息 id}-{序号}`，角标只滚动到当前这条回答的来源。
