# 会议纪要自动分析 — CLI 集成 + 定时任务设计

> **状态**：规划中（未实施）
> **日期**：2026-11-12
> **需求来源**：定时检查腾讯会议新结束的会议 → 生成纪要分析报告 → 输出到对话

## 一、需求

1. **触发**：定时任务（每 2 小时），不做实时 Webhook 监控
2. **数据获取**：通过 `tmeet` CLI（腾讯会议官方命令行工具）获取会议纪要
3. **分析生成**：项目内的 Agent（ChatRuntime + DeepSeek）生成分析报告
4. **结果输出**：输出到对话（前端聊天页可见），**不保存到文件**
5. **面试类会议**：额外做"回答不足分析"

**核心设计问题**：如何集成 CLI 工具（`tmeet`），后续会有很多类似 CLI 需要集成

## 二、CLI 集成框架（核心设计）

新建 `backend/app/integrations/` 目录，**三层抽象**：

```
app/integrations/
    __init__.py
    base.py          # CliRunner + CliResult + CliError（通用层）
    tmeet.py         # TmeetAdapter（tmeet 专属）
    registry.py      # IntegrationRegistry（发现与注册）
```

### 2.1 通用层 `base.py`

```python
@dataclass(frozen=True)
class CliResult:
    """CLI 执行结果。"""
    stdout: str
    stderr: str
    exit_code: int

    @property
    def ok(self) -> bool: ...        # exit_code == 0
    @property
    def json(self) -> Any: ...       # json.loads(stdout)，失败抛 CliError

class CliError(Exception):
    """CLI 执行异常，含分类错误码。"""
    code: str     # "not_logged_in" | "timeout" | "permission_denied" | "command_failed" | ...
    message: str

class CliRunner:
    """通用 CLI 执行器：子进程管理、超时、错误分类、防注入。"""

    async def run(self, args: list[str], timeout: float) -> CliResult:
        """执行 CLI 命令。
        - create_subprocess_exec（不经 shell，防注入）
        - asyncio.wait_for 超时后 kill 进程
        - stderr 记日志，stdout 返回
        """
    async def run_json(self, args: list[str], timeout: float) -> Any:
        """执行并解析 JSON 输出。"""
```

**错误分类逻辑**（集中在 `CliRunner` 内）：

| 退出码/stderr 模式 | CliError.code |
|---|---|
| stderr 含 `user config is empty` | `not_logged_in` |
| 退出码非 0 + stderr 含 `permission`/`forbidden` | `permission_denied` |
| 超时 | `timeout` |
| 其他非 0 退出码 | `command_failed` |
| stdout 非合法 JSON | `invalid_output` |

### 2.2 tmeet 适配器 `tmeet.py`

```python
class TmeetAdapter:
    """腾讯会议 CLI 适配器：封装 tmeet minutes 子命令。"""

    def __init__(self, runner: CliRunner, cli_path: str = "tmeet"):
        self._runner = runner
        self._cli_path = cli_path

    async def search_minutes(self, start: str, end: str, page_size: int = 50) -> list[MeetingBrief]:
        """搜索指定时间范围内的会议纪要。
        tmeet minutes search --start <start> --end <end> --page-size 50 --format json
        """

    async def get_minutes(self, minute_id: str) -> MeetingMinutes:
        """获取稳态纪要（overview / summary_points / todos / subject）。
        tmeet minutes get --minute-id <id>
        """

    async def get_short_summary(self, minute_id: str, page_size: int = 100) -> ShortSummary:
        """获取带时间戳的滚动纪要明细。
        tmeet minutes get --short-summary --minute-id <id> --page-size 100
        """
```

### 2.3 注册与发现 `registry.py`

```python
class IntegrationRegistry:
    """集成适配器注册表；启动时构建，供运行时按名查找。"""

    def register(self, adapter: CliAdapter) -> None: ...
    def get(self, name: str) -> CliAdapter | None: ...
    def all(self) -> tuple[CliAdapter, ...]: ...
```

**扩展性**：新增 CLI 只需三步：
1. `app/integrations/<name>.py` 实现适配器
2. `registry.register(XxxAdapter())` 注册
3. 可选：在 `capabilities/builtins/` 里包一层 ToolSpec 暴露给 Agent

## 三、定时任务：MeetingMonitorRuntime

仿 `ScheduleRuntime` 模式（advisory lock + 轮询 + asyncio.Event）：

```
MeetingMonitorRuntime（每 N 小时触发）
    ├─ ① tmeet_adapter.search_minutes(最近2小时)
    ├─ ② 比对去重台账（DB 表 meeting_monitors）
    ├─ ③ 对新会议：get_minutes + get_short_summary
    ├─ ④ 生成分析（ChatRuntime.create_run → Agent）
    └─ ⑤ 更新台账状态
```

- **advisory lock**：`MEETING_MONITOR_LOCK = 782341921`（避开已用值）
- **状态机**：`detected → fetching → analyzing → completed | failed`
- **去重**：DB 表 `meeting_monitors` 的 `minute_id` 唯一约束
- **分析生成**：复用 `ChatRuntime.create_run() + schedule()`（与 `ScheduleRuntime._execute()` 同款）
- **输出**：分析结果作为对话消息（前端聊天页可见）
- **错误处理**：`not_logged_in` → 静默结束本次执行，不重试

## 五、分析生成（Agent 提示词）

新增 `MEETING_ANALYSIS_PROMPT` 到 `capabilities/prompts.py`：

**面试类**（subject 含 面试/复试/初试/一面/二面/终面/HR/候选人）：
- 会议基本信息（主题、会议号、起止时间、时长、参会人）
- 一句话结论
- 分议题/任务的要点梳理（关键节点标注时间戳）
- 待办清单（谁、做什么、何时）
- **回答不足分析**（逐条：时间戳、被问什么、问题定性、改进话术）
- 下次必须补齐的准备项

**普通会议**：
- 会议基本信息、一句话结论、分议题要点、待办清单
- 不做任何评价

## 八、关键设计优势

| 设计点 | 优势 |
|---|---|
| CliRunner 通用层 | 任何 CLI 都能用，超时/错误分类/防注入统一 |
| Adapter 模式 | 每个 CLI 一个文件，类型安全，易测试 |
| 错误分类标准 | `not_logged_in`/`timeout`/`permission_denied` 等标准错误码 |
| 防注入 | `create_subprocess_exec` 不经 shell |
| 复用 ChatRuntime | 分析生成走现有 Agent 链路，不新建执行器 |
| DB 去重台账 | 分钟 ID 唯一约束，可靠去重 |
| 扩展性 | 新增 CLI = 新增 Adapter 文件 + 注册 |
