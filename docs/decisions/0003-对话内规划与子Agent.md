# 0003：对话作为规划与子 Agent 的统一入口

日期：2026-11-05。状态：已采用。

## 背景

用户明确纠正产品方向：规划与子 Agent 是问答的能力，不应另建“计划与执行”标签页，也不要求只读任务先编辑 JSON 再确认。0002 的独立 Task 方案不能作为默认产品交互。

## 选择

在现有对话 Deep Agents 图中注册 update_plan 与 delegate_tasks，通过可信运行绑定的 ChatAgentExecutor 执行。每个子 Agent 是独立 Deep Agents 图，拥有独立消息上下文，默认分析员/复核员职责，最多两个并行、单层委派。计划是公开工作步骤，不包含私有推理。

复用 tool_calls 归属、状态与结果字段保存计划更新、子任务和模型重试状态；无需增加数据表。SSE 继续发布对话快照，消息内执行卡片轮询当前 Run 的审计接口。工具校验与数据库权限继续由服务端执行，模型不传身份。

模型请求使用原有网络错误分类与退避，SDK max_retries=0；仅重试当前图的模型动作，不重启整轮图。SDK 仍接收流式响应，但前端按完整成功动作发布正文，以防半段失败输出与重试答案重复拼接。

## 取舍

- 直接把旧任务表单嵌入问答：实现快，但保留手工 JSON 和确认流程，且无法提供子 Agent 工具循环，未采用。
- 直接开放 SDK 全部内置工具和默认子 Agent：接入快，但同时暴露文件等无产品授权的能力，未采用。
- 显式受控工具及独立子图：可复用权限和审计、限制递归与并行；代价是自行维护进度记录、配额与取消传播，已采用。

## 恢复边界

对话运行刷新可恢复展示，关闭页面仍可后台执行；进程重启会收敛为失败。当前没有对话图节点检查点，不自动恢复任意工具循环。独立 Task 后端和 0008 数据保留兼容，其动作检查点恢复能力不移植成虚假对话恢复承诺。

后续如需要对话图断点恢复，应单独设计 checkpointer、工具动作标识、幂等与副作用恢复策略。
