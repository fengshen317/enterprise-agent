# ADR 0001：本地运行与工程基础

日期：2026-11-03。状态：采用；本机数据库连接策略已更新为复用已有服务。

## 背景

项目用于学习企业级 Agent 开发与锻炼工程能力。用户明确当前只考虑本地执行。已有静态原型，正式应用从阶段一开始。

## 决策

1. 当前复用已有 PostgreSQL 服务，使用 postgres 用户 + 本地 Uvicorn + Vite，不要求 Docker，不发布正式应用到在线 Sites。既有在线原型保持不变。
2. 采用模块化单体目录，暂不引入队列、微服务、Kubernetes、Temporal 或模型网关。
3. Python 使用 3.13，uv 管理依赖和锁文件；前端使用 Vue 3、TypeScript、Vite，npm 管理锁文件。
4. 使用 SQLAlchemy 异步引擎与 asyncpg。最初尝试的 psycopg 异步迁移在 Windows 默认 ProactorEventLoop 中失败，改用 asyncpg 后真实迁移与应用查询通过，无需全局切换事件循环策略。
5. 数据库结构由 Alembic 显式管理，初始化 system_metadata 标记用于就绪检查。
6. liveness 与 readiness 分离；统一错误响应和 JSON 应用日志作为后续可观测性的基础。
7. 前端只实现真实系统状态页，不将原型的模拟业务能力包装为已实现功能。
8. 先采用本地自动检查脚本；CI 在后续阶段按仓库托管方式接入。

## 取舍

- 本机数据库需要开发者安装和配置，但符合当前环境与本地执行目标。容器化留待未来有明确需要时评估。
- asyncpg 让当前 Windows 开发链路保持简单；后续 Agent 检查点驱动可独立选择，但必须验证连接池与事件循环生命周期。
- 基础设施表增加一个轻量迁移，用来证明迁移执行和真实数据库查询；不提前引入对话业务表。
- 普通测试使用会话替身，真实数据库迁移单独验收；两者证据分别记录。

## 依据

- 项目阶段路线图和用户关于仅本地运行的明确要求。
- [SQLAlchemy PostgreSQL 异步驱动文档](https://docs.sqlalchemy.org/en/20/dialects/postgresql.html#module-sqlalchemy.dialects.postgresql.asyncpg)。
- 本机真实迁移、后端契约测试、前端测试及 HTTP 联调，详见阶段一验收记录。

## 数据库连接策略修订

用户明确要求不新建实例，使用 postgres 用户。默认地址改为 127.0.0.1:5432，真实密码由用户在 backend/.env 配置。原项目实例已停止、数据保留；不再将其作为开发启动要求。不修改已有 postgres 密码。现有服务连接、迁移和集成测试需要重新验证。

## 独立数据库配置字段

按用户要求取消应用连接串填写，改为 EA_DATABASE_HOST、EA_DATABASE_PORT、EA_DATABASE_USER、EA_DATABASE_PASSWORD、EA_DATABASE_NAME。由 SQLAlchemy URL.create 构造连接对象，密码按原文传入。数据库引擎和 Alembic 共用该配置，旧 EA_DATABASE_URL 不再使用。集成测试的 EA_TEST_DATABASE_URL 仍为单独的测试入口，解析后映射为同样的独立字段。

## 测试库配置补全

新增 EA_TEST_DATABASE_NAME，开发库与测试库共用地址、端口、用户名及原文密码，只替换数据库名。测试库连接由 test_sqlalchemy_url 生成，并拒绝与开发库相同或不以 _test 结尾的库名。旧测试连接串 EA_TEST_DATABASE_URL 不再读取。配置了测试库名时完整 pytest 执行真实数据库集成测试；基础检查默认排除 integration。
