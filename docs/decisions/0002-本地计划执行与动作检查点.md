# 0002：本地计划执行与动作检查点

日期：2026-11-04。状态：已采用（0008）。

当前只有一套本机服务和一个只读业务工具。直接引入分布式队列、自由子 Agent 与独立 LangGraph checkpoint 提交，会增加调度、授权和事务对账复杂度。

选择由 PostgreSQL 存储任务、计划、步骤、逻辑动作、实际请求尝试和有序事件；应用生命周期启动本地调度器。单调度器 advisory lock 限制本地进程，TaskRun 行锁和 fencing token 保护领取、取消与恢复。外部请求与等待期间不持有数据库会话。

当前任务每步是用户确认的单个模型或只读工具动作。TaskAction 成功结果与请求尝试终态在同一事务提交，作为该动作的应用级检查点。即使进程在动作完成后、步骤完成提交前中断，恢复也先读账本，不重做成功动作。模型调用只展示完整结果，避免失败片段重复拼接。

这不同于 LangGraph 内部任意节点的 checkpoint，不支持任意 token 位置续跑。之后引入步骤内多轮 ReAct 时，应使用稳定逻辑操作 ID 连接 SDK 状态与业务账本，处理两套事务之间的窗口，不能仅依靠 SDK checkpoint 保证外部 exactly-once。

默认串行执行，可配置同时执行两条依赖已满足的独立分支。每个并发动作独立会话；一分支失败会停止本批未完成分支并保留已提交结果。手动重试创建新的执行并重新规划确认，不自动复用可能过时的统计；自动网络重试仍在原执行中只重试失败动作。

取舍：当前不需要 Redis/Celery/MCP，能够练习明确的状态机、幂等、故障注入和恢复；进程停止期间不能继续工作，租约过期最多等待30秒后恢复，本机吞吐有明确上限。独立 Worker、子 Agent 与写入审批保留后续实施。
